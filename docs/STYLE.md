# 문서 규칙 — 이 저장소의 글을 쓰는 법

| 항목 | 값 |
|---|---|
| 문서 | STYLE |
| 작성일 | 2026-09-18 |
| 적용 | `README.md`, `docs/*.md`, 커밋 메시지, 화면 문장 |

읽는 사람은 이 제품을 모른다. 그리고 시간이 없다. 두 가지를 동시에 만족시키는 방법은 **짧게 쓰고 근거를 옆에 붙이는 것**뿐이다.

---

## 1. 문장

- **단문·능동.** 한 문장에 주장 하나. "~되어지다", "~에 대한", "~을 진행하다" 를 쓰지 않는다.
- **결론을 먼저.** 근거는 뒤에. 읽는 사람이 첫 줄에서 멈춰도 결론은 가져가게 한다.
- **형용사 대신 측정값.** "빠르다" 가 아니라 "gzip 40KB". "정확하다" 가 아니라 "정수 비교로 5%를 가른다".
- **부정형으로 경계를 적는다.** "판정하지 않는다", "저장하지 않는다", "추정치를 만들지 않는다". 무엇을 하지 않는지가 이 제품의 절반이다.

## 2. 숫자

- **모수와 단위를 값 옆에 쓴다.** `31.95%` 가 아니라 `44,877건 중 31.95%`.
- **반올림 방식을 명시한다.** 사사오입인지 은행원 반올림인지. 파이썬 `round` 와 자바스크립트 `Math.round` 는 다르다.
- **출처를 `anchors.json` 으로 단일화한다.** 문서에 숫자를 손으로 적을 때는 그 값이 `node scripts/test_anchors_docs.mjs` 의 대상인지 확인한다. 대상이 아니면 왜 아닌지를 한 줄로 적는다.
- **계열이 다른 숫자를 한 문장에 섞지 않는다.** 섞어야 하면 두 문장으로 나누고 각각 모수를 붙인다.
- **계산된 주장에는 실행 가능한 검증을 붙인다.** 숫자를 내는 코드에는 자체 검증을, 사실 주장에는 근거 등급과 확인일을. **검증 없는 수치는 결과가 아니라 가설이다.**

## 3. 근거

| 등급 | 뜻 | 표기 |
|---|---|---|
| **A** | 원문·1차 자료를 직접 확인 | 인용 + 링크 + 확인일 |
| **B** | 정황과 규정으로 추론. 직접 관측이 아님 | "근거 등급 B" 를 문장 안에 적는다 |
| **C** | 2차 보도·요약 | 출처와 함께, 수치는 인용하지 않는다 |
| **X** | 미확인 | "미확인" 이라고 적는다. 빈칸으로 두지 않는다 |

- **부재는 "없다" 가 아니라 "검색어와 날짜 기준 미발견" 이다.**
- **재현되지 않으면 재현되지 않았다고 쓴다.** 명세에 적힌 실패 사례라도 마찬가지다.
- **문서에 없는 사실을 단정하지 않는다.**

## 4. 구조

- **Why → What → How.** 각 절도 필요하면 같은 순서로 쪼갠다. 왜가 없는 절은 지운다.
- **표를 먼저 쓴다.** 항목이 셋을 넘으면 문단이 아니라 표다.
- **문서 머리에 메타 표.** 문서명·작성일·상태·읽는 사람.
- **한 문서는 한 질문에 답한다.** PRD 는 왜, SPEC 은 무엇을, ARCHITECTURE 는 어떻게, TEST 는 무엇을 검사하는지. 답이 겹치면 한쪽이 링크만 남긴다.
- **돌지 않는 명령을 적지 않는다.** 계획은 "아직 없는 것" 절에 따로 적는다.

## 5. 화면 문장

- **모든 상태가 사용자가 읽는 문장으로 끝난다.** 빈 화면·멈춘 스피너는 결말이 아니다.
- **표본 수 `n` 을 같은 문장 안에 쓴다.**
- **넓혔으면 넓혔다고 쓴다.** 어느 단계 기준인지까지.
- **모르면 모른다고 쓴다.** 추정치로 칸을 채우지 않는다.
- **검사가 못 하는 일을 화면이 약속하지 않는다.** "숫자가 하나라도 있으면 버립니다" 라고 쓰려면 검사가 정말 그래야 한다. 아니면 문구를 검사에 맞춘다.

## 6. 커밋 메시지

- 제목은 `분류: 무엇을 했나` 한 줄. 분류는 구현·수정·정합·보안·배포·평가·문서.
- 본문은 **무엇이 틀렸고 왜 그렇게 고쳤는지**. 무엇을 고쳤는지는 diff 가 말한다.
- 마지막 줄에 검증 결과. `검증: ./scripts/test_all.sh — 전부 통과`.
