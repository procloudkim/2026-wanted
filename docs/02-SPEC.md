# 02. 기능 명세 — 갱신 기준선

| 항목 | 값 |
|---|---|
| 문서 | 02-SPEC |
| 작성일 | 2026-09-18 (최종 정합 2026-09-20) |
| 상태 | v1.0 · 데이터 스냅샷 기준일 2026-09-18 |
| 읽는 사람 | 화면을 고치거나 판정 규칙을 바꾸는 사람 |

프레임워크: **Why → What → How**. 모든 기능 블록은 "왜 필요한가 → 무엇을 하는가 → 어떻게 계산·표시하는가" 순서로 쓴다.

**한 줄 정의**: 전월세 갱신을 앞둔 세입자가 집주인에게 제시받은 조건을, 같은 단지·같은 평형에서 실제로 신고된 갱신 계약의 분포와 대조해 다음 행동을 정하도록 돕는 웹 서비스.

**설계 원칙 (이 문서 전체에 적용)**

1. **판정은 코드가 한다.** 사용자에게 보이는 모든 숫자는 §3의 산술 규칙 7종이 낸 값이다. AI는 §6의 두 단계만 맡고, 그 출력은 판정 파이프라인에 들어가지 못한다.
2. **표본 수를 숨기지 않는다.** 분포·백분위·중앙값을 보여 주는 모든 문장에는 그 숫자를 만든 표본 수 `n`이 같은 문장 안에 있다.
3. **분모가 다른 두 측정을 한 문장에 섞지 않는다.** 이 문서의 서울 전체 집계값은 전부 한 계열이다 — 국토부 4종 API, 서울 25개 자치구, 최근 12개월, 전세→전세 갱신 85,691건. 제품을 정하기 전에 쓴 초기 탐색 계열은 모수가 달라 `01-PRD 부록 A` 에만 둔다.
4. **모르는 것은 계산하지 않는다.** 표본이 없으면 추정치를 만들지 않고 "판정 불가"로 끝낸다.
5. **조용히 통과하는 경로가 없다.** §5의 모든 상태에 사용자가 읽는 결말 문장이 있다.

## 1. 범위와 용어

### 1.1 Why — 같은 단어를 서로 다르게 쓰면 판정이 흔들린다

"갱신"이라는 한 단어에 **갱신요구권 행사 갱신 / 합의 갱신 / 묵시적 갱신** 셋이 섞여 있고, 셋은 5% 상한 적용 여부가 서로 다르다. 원천 데이터의 `계약구분=갱신` 한 칸에도 셋이 섞여 있다. 용어를 먼저 고정하지 않으면 같은 화면에서 서로 다른 뜻의 "5%"가 나온다.

### 1.2 What — 이 문서에서 쓰는 말

| 용어 | 이 문서에서의 정의 | 판정에 쓰는가 |
|---|---|---|
| **갱신요구권** | 주택임대차보호법 제6조의3에 따라 임차인이 임대차 기간 만료 **6개월 전부터 2개월 전까지** 사이에 갱신을 요구할 수 있는 권리. 같은 주택에서 1회 한정 | 기한 계산(R6)에 쓴다. 효력·성립 여부는 판정하지 않는다 |
| **행사 갱신** | 임차인이 갱신요구권을 행사해 성립한 갱신. 원천 데이터에서 `갱신요구권 사용='사용'`(국토부) 또는 `계약갱신권사용여부='○'`(서울)로 기록된 행 | R4의 한 집단 |
| **합의 갱신** | 갱신요구권 행사 없이 당사자 합의로 새로 맺은 갱신. 데이터에서는 `계약구분='갱신'`이면서 갱신요구권 칸이 비어 있는 행 | R4의 다른 한 집단 |
| **묵시적 갱신** | 만기까지 양쪽 모두 통지가 없어 전 임대차와 동일한 조건으로 갱신된 것으로 보는 상태 | 데이터에서 합의 갱신과 **구분되지 않는다.** 분포 판정에 쓰지 않고, 기한 화면의 경로 안내에만 쓴다 |
| **행사 기록 있음 / 행사 기록 없음** | 위 두 집단을 화면에 부르는 이름. **"미사용"이라고 쓰지 않는다.** 근거 등급 B — 법정 신고서 서식이 갱신 계약에 대해 "행사/미행사" 2지 택일만 두고 있고 데이터 생산기관도 빈 값을 미사용으로 집계하지만, 공표 데이터의 인코딩이 손실적이어서 "미기재"가 섞여 있어도 데이터만으로는 분리할 수 없다 | R4 |
| **신규 계약 행** | `계약구분='신규'`인 행. 갱신요구권 칸이 **100% 비어 있고**, 그 빈 값은 "해당 없음"이다 | **행사 기록 없음 집단에 절대 합산하지 않는다**(§5 O-05) |
| **전세→전세 갱신** | 종전 월세 = 0 이고 현재 월세 = 0 인 갱신 계약. 보증금 하나로 인상률이 정의되는 유일한 구간 | R1·R3·R4·R5의 모집단 |
| **코호트** | 판정 기준이 되는 비교 집단. 기본 단위 = `자치구 + 법정동 + 건물명 + 전용면적 10㎡ 구간`, 필터 = `계약구분=갱신 AND 종전월세=0 AND 현월세=0` | R3·R5 |
| **코호트 레벨** | 표본이 모자랄 때 넓히는 단계. 1 단지·면적대 → 2 단지 전체 면적 → 3 법정동·면적대 → 4 법정동 전체 → 5 자치구 전체. 단지 단계(1·2)는 **아파트에만** 만든다. **넓힌 사실과 어느 단계인지를 화면에 적는다** | R5-1 |
| **백분위(상위 X%)** | 코호트의 **행사 기록이 없는 갱신** 안에서 내 인상률보다 **크거나 같은** 계약의 비율. `상위 X% = |{r ∈ C_nr : r ≥ mine}| / n × 100`. 행사 기록 있는 갱신은 5% 상한이 걸린 계약이라 섞지 않는다 | R3 |
| **기준일(asof)** | 판정에 쓴 데이터 스냅샷의 생성일. 화면 상단에 항상 표시한다 | 전 화면 고정 |
| **법정 기한 창 / 마감** | 창 시작 = 만기일 − 6개월, 마감 = 만기일 − 2개월. **개월 단위 계산이 정답이고 D-표기는 보조다** | R6 |
| **5% 상한** | 주택임대차보호법 제7조의 20분의 1. **갱신요구권을 행사한 갱신에 적용되고, 합의 갱신에는 적용되지 않는다** | R2 |
| **초과 차액** | `제시 보증금 − 종전 보증금 × 1.05`. **위법 금액이 아니라** "갱신요구권을 행사했을 때의 상한과 실제 제시 조건의 차이"다 | R2 |
| **이탈 차액** | 같은 단지·평형의 **신규 전세 보증금 중앙값 − 내 갱신 후 보증금**. 양수면 내가 시세보다 싸게 사는 것 | R5 |
| **환산 전환율** | 월세가 붙는 조건에서 `(월세 × 12) ÷ 보증금 감액분`. 시장 데이터 역산값이고 **법정 전월세전환율 한도 판정이 아니다** | R7 |
| **금액 단위** | 모든 내부 금액은 **만원 단위 정수**. 표시는 1억원 이상이면 `N억 M,MMM만원` | 전 규칙 |

## 2. 입력 명세 — 사용자가 넣는 것

### 2.1 Why — 입력이 7개를 넘으면 사용자는 창을 닫고, 7개가 안 되면 판정이 안 선다

판정에 실제로 필요한 값은 **코호트를 특정하는 값 3개**(자치구·법정동·건물명, 전용면적)와 **산술에 들어가는 값 3개**(만기일, 현재 보증금·월세, 제시 조건)뿐이다. 그 외의 값은 받지 않는다. 이름·연락처·동·호수·계약서 파일·소득 정보는 어떤 화면에서도 요구하지 않는다(§8.4).

### 2.2 What — 최소 입력 6개와 선택 입력 3개

| ID | 필드 | 필수 | 형식 | 검증 규칙 | 실패 메시지 (그대로 표시) |
|---|---|---|---|---|---|

| I10 | 갱신요구권 기사용 여부 | 선택 | `예 / 아니오 / 모름`, 기본값 `모름` | `예`면 O-01 오버레이 | — |

|---|---|---|---|
| I8-a **금액 직접 입력**(기본) | 제시 보증금(만원 정수) + 제시 월세(만원 정수, 기본 0) | `0 ≤ 보증금 ≤ 500000`, `0 ≤ 월세 ≤ 1000`. 보증금·월세 둘 다 0이면 거부 | "제시받은 보증금과 월세를 넣어 주세요. 둘 다 0일 수는 없습니다." |

| I8-c **문장 붙여넣기** | 자유 텍스트 **1~2,000자**(`parse.js` 구현값) | AI 변환(§6.1) → **사용자 확인 폼** → I8-a와 같은 형태로 확정. 변환 실패·타임아웃·스키마 위반 시 즉시 I8-a 폼으로 폴백 | "받으신 문장에서 금액을 찾지 못했습니다. 아래에 직접 넣어 주세요." |

### 2.3 How — 검증 순서와 입력 상태 저장

```
입력 검증 파이프라인 (앞 단계가 실패하면 뒤 단계를 실행하지 않는다)
  1) 형식 검증      : 타입·자릿수·범위. 실패 → 해당 필드 옆에 실패 메시지, 다음 단계 없음

  4) 계산 입력 확정 : {코호트 키, 종전 보증금·월세, 제시 보증금·월세, 만기일, 기준일}
```

### 3.1 R1 — 인상률 계산

**Why**: 사용자가 받은 조건을 다른 모든 규칙과 비교 가능한 하나의 스칼라로 바꾼다. 이 값이 없으면 백분위도 분포 비교도 성립하지 않는다.

**What**: 종전 보증금 대비 제시 보증금의 변동률.

| 항목 | 내용 |
|---|---|
| 입력 | `prev`(종전 보증금, 만원 정수 > 0), `now`(제시 보증금, 만원 정수 ≥ 0), `prev_rent`, `now_rent` |
| 출력 | `rate_pct`(소수 2자리), `is_exact_cap`(정확히 +5.00%인가), `is_over_cap` |
| 경계값 | `prev = 0` → **계산 중단**, `E-RATE-DIV0`. `prev_rent > 0 or now_rent > 0` → **R1 사용 금지**, M-04로 분기해 R7을 쓴다. `now < prev` → 감액(음수 인상률)이고 정상 값이다 |
| 반올림 | 표시만 소수 2자리. 5% 동치·초과 판정에는 **표시값을 쓰지 않는다** |

**How**

```python
def r1_rate(prev, now, prev_rent, now_rent):
    assert prev_rent == 0 and now_rent == 0, "월세 혼합은 R7로 간다"
    if prev <= 0:
        return ERROR("E-RATE-DIV0")
    rate = (now - prev) / prev                 # 실수, 표시용
    # 5% 동치/초과는 정수 비교로만 판정한다. 0.05 부동소수 비교를 쓰지 않는다.
    exact_cap = (20 * (now - prev) == prev)    # now == prev * 1.05
    over_cap  = (20 * (now - prev) >  prev)
    return {"rate_pct": round2(rate * 100), "is_exact_cap": exact_cap, "is_over_cap": over_cap}
```

> 왜 정수 비교인가: 데이터의 금액이 만원 단위 정수이므로 `20 × 증감액`과 `종전 보증금`을 비교하면 오차 없이 5%를 가른다. 실수로 `rate > 0.05`를 쓰면 정확히 5.00%인 계약 일부가 초과로 잘못 분류된다. 전세→전세 갱신의 **26.51%(22,719건 / 85,691건)가 정확히 +5.00%**라 이 오분류의 영향이 크다.

### 3.2 R2 — 5% 상한 대비 초과 차액

**Why**: 사용자가 실제로 결정해야 하는 것은 퍼센트가 아니라 금액이다. "8%"는 감각이 없지만 "1,800만원"은 있다.

**What**: 갱신요구권을 행사했을 때의 상한액과 제시 조건의 금액 차이.

| 항목 | 내용 |
|---|---|
| 입력 | `prev`, `now`(만원 정수) |
| 출력 | `cap_deposit`(상한액), `excess`(초과 차액), `over`(초과 여부) |
| 경계값 | `over = false`면 `excess`를 0으로 두고 화면에서 초과 문장을 **렌더하지 않는다**(음수 차액을 "여유"로 포장하지 않는다). 합의 갱신 경로에서는 초과 차액을 **"위법 금액"으로 표기하지 않는다** |
| 반올림 | `cap_deposit`은 만원 단위 **버림**(사용자가 더 내야 할 근거로 쓰이지 않게). `excess`는 버림된 상한액이 아니라 **정확한 상한값 기준으로 계산한 뒤 만원 단위 반올림** |

**How**

```python
CAP_NUM, CAP_DEN = 21, 20        # ×1.05 를 유리수로 다룬다

def r2_cap(prev, now):
    cap_exact   = prev * CAP_NUM / CAP_DEN          # 정확값
    cap_display = (prev * CAP_NUM) // CAP_DEN       # 표시용, 버림
    over        = (20 * (now - prev) > prev)
    excess      = round0(now - cap_exact) if over else 0
    return {"deposit": cap_display, "excess": excess, "over": over,
            "rate_pct": 5.00}
```

**예시 (연우, 종전 6억원)**: `cap_display = 60000 × 21 // 20 = 63000만원`. 제시 64,800만원 → `over = true`, `excess = 64800 − 63000 = 1800만원`.

**참조 앵커**: 서울 최근 12개월 전세→전세 갱신 중 **행사 기록 없음 44,877건**의 초과 차액은 **건당 중앙값 2,400만원**이다. 이 값은 "위법 금액의 중앙값"이 아니라 "갱신요구권을 행사했을 때의 상한과 실제 계약의 차이"의 중앙값이다.

### 3.3 R3 — 코호트 백분위

**Why**: 5%라는 법정 기준선 하나만으로는 "이 단지에서 8%가 흔한 값인지 드문 값인지"를 알 수 없다. 사용자가 협상 테이블에서 실제로 필요한 것은 같은 단지·같은 평형의 실제 분포다.

그런데 그 분포에 **행사 기록이 있는 갱신을 섞으면 안 된다.** 그 계약들은 5% 상한이 걸린 계약이라, 섞으면 제시안이 실제보다 드물어 보인다. 실측 예시로, 강남구 대치동 전용 80-90㎡ 에서 +8% 는 두 집단을 합치면 316건 중 상위 16.8%이지만, 행사 기록이 없는 111건 안에서는 상위 47.7%로 거의 중앙값이다(2026-10-25 검토, `scripts/test_rules.mjs` R3). 권리를 쓸 수 있는 세입자에게는 백분위보다 5% 상한이 답이고, 이미 쓴 세입자가 견줄 대상은 행사 기록이 없는 쪽이다. 합친 숫자는 어느 쪽에도 맞지 않는다. 2026-10-25 이전 구현은 두 벡터를 합쳐 계산했다.

**What**: 내 인상률이 같은 코호트의 **행사 기록이 없는 갱신** 안에서 상위 몇 %인지.

| 항목 | 내용 |
|---|---|
| 입력 | 코호트 키 `(자치구, 법정동, 건물명, 면적 구간)`, 내 `rate` |
| 출력 | `n`(행사 기록이 없는 갱신 수), `median_pct`, `p90_pct`, `top_share_pct`(상위 X%), `tie_at_cap_n`(정확히 5.00%인 건수), `recorded`(같은 범위의 행사 기록 있는 갱신 건수와 5% 이하 비율. 비교에서 뺀 이유를 화면에 적는 데만 쓴다), `level`, `widened` |
| 경계값 | `n = 0` → M-08(결과 0건). `n < 3` → **백분위를 계산하지 않고** R5-1의 확장 절차로 간다. 행사 기록 있는 갱신은 `n`을 채우지 않는다. 확장 후에도 `n < 3` → 판정 불가로 끝낸다 |
| 반올림 | 백분위·중앙값·p90 모두 소수 1~2자리 반올림. `n`은 정수 그대로 |

**코호트 필터 (SQL 형태로 못 박는다)**

```sql
SELECT (deposit - prev_deposit) * 1.0 / prev_deposit AS rate
FROM   rent_snapshot
WHERE  contract_type = '갱신'          -- 신규 행은 절대 포함하지 않는다
  AND  prev_rent = 0 AND rent = 0      -- 전세→전세만
  AND  prev_deposit > 0
  AND  rr_right = ''                   -- 행사 기록이 없는 갱신만. 5% 상한이 걸린 계약을 섞지 않는다
  AND  gu = :gu AND dong = :dong
  AND  building_norm = :building_norm
  AND  FLOOR(area / 10) = FLOOR(:area / 10)   -- 전용면적 10㎡ 구간
```

**How**

```python
def r3_percentile(rates, mine):                     # rates: 위 필터를 지난 행사 기록 없는 갱신
    n = len(rates)
    if n < 3:
        return NEED_WIDEN(n)                        # R5-1로 넘어간다
    s = sorted(rates)
    # 상위 X% : 나보다 크거나 같은 계약의 비율 (동률 포함)
    above = sum(1 for r in s if r >= mine)
    return {
        "n": n,
        "median_pct":  round2(quantile(s, 50) * 100),
        "p90_pct":     round2(quantile(s, 90) * 100),
        "top_share_pct": round1(above / n * 100),
        # 5.00% 동률이 몰려 있어 백분위가 계단처럼 움직인다. 동률 수를 함께 낸다.
        "tie_at_cap_n": sum(1 for r in s if is_exact_cap_rate(r)),
    }

def quantile(sorted_vals, p):                        # 최근접 순위법
    k = int(round((len(sorted_vals) - 1) * p / 100))
    return sorted_vals[min(k, len(sorted_vals) - 1)]
```

**동률 경고(필수)**: `tie_at_cap_n / n ≥ 0.20`이면 화면에 한 줄을 추가한다 — "이 갱신 **n건 중 m건이 정확히 +5.00%**입니다. 5.00% 부근에서는 백분위가 한 계단씩 크게 움직입니다."

**비교에서 뺀 쪽을 숨기지 않는다(필수)**: 머리 문장 바로 아래에 "같은 범위에서 행사 기록이 있는 갱신 **{recorded.n}건**은 **{recorded.within_cap_pct}%**가 5% 이하였습니다. 5% 상한이 걸리는 계약이라 위 비교에 넣지 않았습니다."를 붙인다.

**이상치 방어**: 종전 보증금이 100만원 미만인 행은 코호트에서 제외한다. 실제 데이터에 `종전 4만원 → 현 48,500만원`(+1,212,400%) 같은 행이 있다(수집 596,178행 중 인상률 −90~300% 밖이라 버린 행이 61건, 0.07%). **평균을 쓰지 않고 중앙값·백분위만 쓰는 이유가 이것이다.**

### 3.4 R4 — 행사 기록 유무별 분포 비교

**Why**: 같은 법·같은 해·같은 상품인데 두 집단의 분포가 완전히 갈린다. 사용자가 받은 조건이 "어느 쪽 분포의 숫자인지"를 아는 것이 이 서비스의 핵심 판정이다.

**What**: 내 인상률을 두 집단의 5% 초과 비율 위에 놓는다.

| 항목 | 내용 |
|---|---|
| 입력 | 내 `rate`, 스냅샷 상수(아래 표) |
| 출력 | `groups` 객체 — 두 집단의 `n`과 `over_cap_share_pct`, 그리고 내 값이 각 집단에서 어느 쪽에 속하는지 |
| 경계값 | 월세가 섞이면 **이 비교를 잠근다**(아래 경고 참조). `신규` 행이 한 건이라도 섞여 있으면 판정 전체를 중단한다(§5 O-05) |
| 반올림 | 비율 소수 2자리 |

**상수 (스냅샷 기준일 2026-09-18, 모수 = 서울 25개 자치구 × 최근 12개월 전세→전세 갱신 85,691건)**
값은 `dist/data/anchors.json` 에서 온다. 이 표를 손으로 고치면 `node scripts/test_anchors_docs.mjs` 가 먼저 깨진다.

| 집단 | n | 5% 초과 비율 | 비고 |
|---|---|---|---|
| 행사 기록 있음 | 40,814 | **0.37%** | 5% 상한이 사실상 물리적으로 지켜진다 |
| 행사 기록 없음 | 44,877 | **31.95%** | 초과 차액 건당 중앙값 2,400만원 |
| 합계 | 85,691 | — | 40,814 + 44,877 = 85,691 |

**How**

```python
def r4_groups(rate_pct, snapshot):
    g = snapshot.groups                       # 위 상수 표
    mine_over = rate_pct > 5.00               # 표시용. 실제 판정은 R1의 정수 비교 결과를 쓴다
    return {
        "scope": snapshot.scope,              # 모수 문자열도 스냅샷에서 온다
        "total_n": g.total_n,                 # 85691
        "recorded":   {"n": g.rec.n,   "over_cap_share_pct": g.rec.share},    # 40814 / 0.37
        "unrecorded": {"n": g.unrec.n, "over_cap_share_pct": g.unrec.share,   # 44877 / 31.95
                       "excess_median": g.unrec.excess_median},               # 2400
        "mine_over_cap": mine_over,
    }
```

**월세 환산 경고(필수, 이 규칙을 쓰는 모든 화면에 고정)**
위 두 숫자는 **월세가 0인 전세→전세 계약만**으로 계산했다. 월세를 환산해 포함하면 5% 초과 비율이 **35~46%** 사이에서 흔들린다(환산 배수 가정에 따라 8%p 이상 변한다). 그래서 월세가 섞인 계약에는 이 비교를 적용하지 않고 R7로 보낸다.

**빈 칸 해석 경고(필수)**
"행사 기록 없음"은 갱신 행의 갱신요구권 칸이 비어 있는 계약을 뜻한다. 법정 신고서 서식이 갱신 계약에 대해 "행사 / 미행사" 2지 택일만 두고 있고 데이터 생산기관도 빈 값을 미사용으로 집계하므로 미행사로 읽지만(근거 등급 **B**), 공표 데이터에 "미기재"가 섞여 있어도 데이터만으로는 분리할 수 없다. **화면 표기는 항상 "행사 기록 없음"이고 "미사용"이라고 쓰지 않는다.**

### 3.5 R5 — 신규 시세 대비 차액 (이탈 차액)

**Why**: "지금 갱신하는 게 이득인가"는 5% 상한과 무관한 별개의 질문이다. 나가면 같은 평형의 신규 전세 시세를 다시 지불해야 한다.

**What**: 같은 단지·같은 면적 구간의 **신규 전세** 보증금 중앙값과 내 갱신 후 보증금의 차이.

| 항목 | 내용 |
|---|---|
| 입력 | 코호트 키, 내 갱신 후 보증금(제시 보증금) |
| 출력 | `new_median`, `n`, `gap`(양수 = 내가 더 싸다), `gap_pct`, `level`, `widened` |
| 경계값 | 신규 표본 `n < 5` → 다음 단계로 넓히고 **넓힌 사실과 어느 단계인지를 화면에 적는다**. 다섯 단계를 다 내려가도 `n < 5` → 이 카드를 **렌더하지 않는다**(다른 물건의 숫자를 붙이지 않는다). 월세 혼합이면 잠근다 |
| 반올림 | 금액 만원 단위 반올림, 비율 소수 1자리 |

**How**

```sql
SELECT deposit FROM rent_snapshot
WHERE contract_type = '신규' AND rent = 0            -- 신규 전세만
  AND gu=:gu AND dong=:dong AND building_norm=:b
  AND FLOOR(area/10) = FLOOR(:area/10)
```

```python
def r5_market(new_deposits, my_deposit):
    n = len(new_deposits)
    if n < 5:
        return WIDEN_OR_HIDE                       # 다음 단계로 확장, 실패하면 카드 자체를 숨긴다
    med = quantile(sorted(new_deposits), 50)
    gap = round0(med - my_deposit)                 # 양수 = 내가 시세보다 싸다
    return {"n": n, "new_median": med, "gap": gap,
            "gap_pct": round1(gap / med * 100)}
```

**참조 앵커**: 같은 단지·같은 면적 구간(1단계)에서 신규 전세 표본 5건 이상을 확보한 갱신 계약 **42,237건**(전세→전세 갱신의 49.29%) 기준, 갱신 보증금이 신규 전세 중앙값보다 **중앙값 6,000만원 낮고**, **81.08%가 시세 이하**다. 단계를 내려갈수록 이 차액은 줄고 4단계부터는 부호가 바뀐다 — 그래서 화면은 **어느 단계의 숫자인지를 같은 문장에 적는다.**

**같은 카드에 반드시 붙는 한계 문장(고정)**: 이 차액에는 **이사비·중개보수·대출 조건이 들어 있지 않고**, 그 값에 실제 매물이 있는지도 이 데이터는 답하지 않는다. 차액이 곧 이득은 아니다.

### 3.6 R5-1 — 표본 수 판정과 코호트 확장

**Why**: 표본 3건짜리 백분위는 숫자처럼 생겼지만 판정이 아니다. 실측(85,691건)에서 갱신 계약이 비교 표본(행사 기록이 없는 갱신, R3) 3건을 만나는 단계는 **1단계 46.95% / 2단계 10.31% / 3단계 35.93% / 4단계 6.02% / 5단계 0.79%**이고, 다섯 단계를 다 내려가도 못 만나는 계약은 **0건**이다. 즉 1단계에서 끝나지 않는 계약이 53.05%라서 **확장은 예외가 아니라 상시 경로**이므로, 어느 단계의 숫자인지를 화면에 적지 않으면 사용자는 전부 단지 단위로 읽는다. 값은 `anchors.ladder` 에서 온다(2026-10-25 R3 표본 정정 전에는 행사 기록을 합쳐 세어 1단계가 59.56%였다).

**What**: 코호트 레벨을 단계적으로 넓히고, 어느 단계에서 몇 건이 나왔는지 그대로 보여 준다.

| 판정 | 최소 표본 | 미달 시 |
|---|---|---|
| R3 백분위 | 행사 기록이 없는 갱신 `n ≥ 3` (권장 5) | 한 단계 확장 |
| R5 신규 시세 중앙값 | `n ≥ 5` | 한 단계 확장, 실패 시 카드 숨김 |
| R4 두 집단 비교 | 서울 전체 상수를 쓰므로 코호트 표본과 무관 | — |

**How**

```python
# 5단계. 단지 단계(1·2)는 원천이 단지 일련번호를 주는 유형(아파트)에만 만든다.
LEVELS = [(1, "단지·면적대"), (2, "단지 전체 면적"), (3, "법정동·면적대"),
          (4, "법정동 전체"), (5, "자치구 전체")]

def r5_1_widen(key, min_n, fetch):
    trail = []                                   # 어느 단계에서 몇 건이 나왔는지 전부 기록
    for code, label in LEVELS:
        rows = fetch(key, code)
        trail.append({"level": code, "label": label, "n": len(rows)})
        if len(rows) >= min_n:
            return {"rows": rows, "level": code, "widened": code != LEVELS[0][0], "trail": trail}
    return {"rows": [], "level": None, "widened": True, "trail": trail}   # 판정 불가
```

**표시 규칙**: `widened = true`면 결과 문장 바로 아래에 확장 경로를 그대로 적는다 — "단지·면적대 **2건** → 단지 전체 면적 **4건** → **이 숫자는 단지 전체 면적 기준입니다.**" 확장은 예외가 아니라 갱신 계약의 53.05%가 지나는 상시 경로다.

### 3.7 R6 — 법정 기한 타임라인

**Why**: 세 가지 결정(행사 / 합의 / 무행동)이 전부 하나의 날짜에 걸려 있는데, 그 날짜를 아무도 알려주지 않는다. 그리고 "만기 1개월 전"이라는 옛 기준이 아직 유통된다. 하루 늦으면 이번 만기에는 권리가 사라진다. 그래서 **마감은 대응일이 아니라 그 전날**로 안내한다 — "2개월 전까지"는 대응일 0시 전까지라서 대응일 당일에 도달하면 이미 늦다(근거는 아래 검증 예시 다음 문단).

**What**: 만기일 1개 입력으로 창 시작일·마감일·남은 일수·경고 단계를 낸다.

| 항목 | 내용 |
|---|---|
| 입력 | `expiry`(만기일), `today`, (선택) `signed`(계약 체결일) |
| 출력 | `start`, `deadline`, `d_day`, `stage`, `basis` |
| 경계값 | **개월 단위 계산이 정답이고 D-180/D-60 표기는 보조다.** 말일 보정은 해당 월의 마지막 날로 고정한다. **마감은 대응일의 전날이다.** `today > deadline` → M-02. `signed < 2020-12-10` → 두 날짜를 모두 표시하고 **이른 쪽을 마감으로 안내한다** |
| 반올림 | 날짜 연산에 시분초를 쓰지 않는다. 모든 비교는 날짜(Asia/Seoul) 단위 |

**How**

```python
def minus_months(d, m):
    y, mo = d.year, d.month - m
    while mo <= 0:
        mo += 12; y -= 1
    last = days_in_month(y, mo)          # 말일 보정: 만기 3/31 - 1개월 = 2/28(29)
    return date(y, mo, min(d.day, last))

def r6_window(expiry, today, signed=None):
    start    = minus_months(expiry, 6)                          # 대응일 0시에 열린다
    deadline = minus_months(expiry, 2) - timedelta(days=1)      # 대응일 0시 전까지 = 그 전날
    note = None
    if signed and signed < date(2020, 12, 10):
        alt = minus_months(expiry, 1) - timedelta(days=1)       # 옛 기준
        note = {"alt_deadline": alt, "text": "기준이 다를 수 있어 두 날짜를 모두 표시합니다"}
        deadline = min(deadline, alt)    # 보수적으로 이른 날짜를 마감으로 안내
    d_day = (deadline - today).days
    stage = ("PASSED" if d_day <  0 else "TODAY" if d_day == 0 else
             "D1" if d_day <= 1 else "D3" if d_day <= 3 else
             "D7" if d_day <= 7 else "D14" if d_day <= 14 else "OPEN")
    return {"start": start, "deadline": deadline, "d_day": d_day,
            "stage": stage, "basis": "months", "note": note}
```

**검증 예시 (표 그대로 테스트 케이스로 쓴다)**

| 만기일 | 창 시작 | 마감 | 비고 |
|---|---|---|---|
| 2026-12-20 | 2026-06-20 | **2026-10-19** | 대응일(10-20)의 전날. D-60 표기(2026-10-21)와도 다르다. 개월 계산이 정답이다 |
| 2027-01-15 | 2026-07-15 | 2026-11-14 | |
| 2026-11-30 | 2026-05-30 | 2026-09-29 | |
| 2026-12-31 | 2026-06-30 | 2026-10-30 | 말일 보정 |
| 2026-04-30 | 2025-10-30 | 2026-02-27 | 말일 보정(2월 28일) 뒤 그 전날 |

**마감을 대응일의 전날로 두는 근거 (확인 2026-10-25, 근거 등급 B)**: 서울시 마을변호사 해설은 "임대차기간 만료일이 2020년 9월 30일인 경우 1개월 전인 2020년 8월 29일까지" 의사표시가 도달해야 한다고 쓴다([서울시 미디어허브](https://mediahub.seoul.go.kr/archives/1294440)). 국토교통부를 인용한 보도는 "계약 만기가 내년 1월 9일이라면 12월 9일 0시 전까지"라고 쓴다([경기일보 2020-11-30](https://kyeonggi.com/article/202011301147368)). 판례는 찾지 못했다. 되돌릴 수 없는 기한이라 해석이 갈려도 이른 쪽을 안내한다. **2026-10-25 이전 구현은 대응일을 마감으로 냈고, 위 표의 기대값도 코드와 같은 작성자가 써서 그대로 통과했다.** 이제 `scripts/test_rules.mjs` 가 바깥 예시 세 건을 기대값으로 대조한다. 창 시작일의 말일 보정(만기 12/31 → 6/30)은 바깥 근거를 찾지 못해 그대로 두었다.

**경고 단계별 화면 동작**

| stage | 조건 | 화면 |
|---|---|---|
| OPEN | d_day > 14 | 상단에 창 시작일·마감일 한 줄 |
| D14 / D7 / D3 / D1 | 각 임계 이하 | 상단 고정 배너 + 남은 일수 |
| TODAY | d_day = 0 | "**오늘이 마지막입니다**" 배너 + 선택 기록 유도 |
| PASSED | d_day < 0 | M-02 모드로 전환 |

### 3.8 R7 — 환산 (월세가 섞이는 조건)

**Why**: 월세가 붙는 순간 보증금 단독 비교가 성립하지 않는다(R1·R3·R4·R5가 전부 무효가 된다). 그런데 사용자는 여전히 "이 조건이 어느 정도인지" 알아야 한다.

**What**: 제시 조건을 보증금 감액분 대비 연 환산 비율로 바꾼다.

| 항목 | 내용 |
|---|---|
| 입력 | `prev_deposit`, `offer_deposit`, `offer_rent`(만원/월) |
| 출력 | `kind`(`CONVERT` / `NET_ADD` / `BOTH_UP`), `annual_rate_pct`, 분포 위치 |
| 경계값 | `감액분 = 0` **and** `월세 > 0` → **전환율 계산 중단**(분모 0), 순증으로 분류하고 `연 부담률 = 월세×12 ÷ 종전 보증금`만 낸다. `감액분 < 0` → 보증금과 월세가 둘 다 오른 것이므로 전환율을 내지 않는다. **법정 전월세전환율 비교는 구현하지 않는다**(기준금리 데이터 없음) |
| 반올림 | 비율 소수 2자리 |

**How**

```python
def r7_convert(prev_deposit, offer_deposit, offer_rent):
    cut = prev_deposit - offer_deposit                # 보증금 감액분
    annual = offer_rent * 12
    if offer_rent == 0:
        return None                                   # 월세 없음 → R1 경로
    if cut == 0:
        return {"kind": "NET_ADD",                    # 전환이 아니라 순증
                "annual_rate_pct": round2(annual / prev_deposit * 100),
                "compare_to_distribution": False}
    if cut < 0:
        return {"kind": "BOTH_UP", "annual_rate_pct": None,
                "compare_to_distribution": False}
    return {"kind": "CONVERT",
            "annual_rate_pct": round2(annual / cut * 100),
            "compare_to_distribution": True}
```

**분포 (서울 전세→월세 갱신 역산, n=3,747)**: p25 **5.74%/년**, 중앙값 **7.38%**, p75 **12.00%**. 상수로 두지 않고 `dist/data/anchors.json` 의 `convert` 를 읽는다 — 다른 두 분포와 같은 빌드에서 나와야 기준일·모수가 어긋나지 않는다. 세 분포 중 **표본이 가장 얇다** — 이 사실을 판정 문장 옆에 항상 붙인다. 단지 단위 비교는 제공하지 않고 **서울 전체 분포를 쓴다고 명시한다.** 스냅샷을 읽지 못하면 전환율만 내고 **분포와 견주지 않는다.**

**예시 (세린, 종전 전세 2억 4,000만원)**

| 조건 | 감액분 | 계산 | 결과 |
|---|---|---|---|
| ① 보증금 24,000 유지 + 월 60 | 0 | 720 ÷ 24,000 | `NET_ADD`, 연 **3.00%** 추가 부담. **분포와 비교하지 않는다** |
| ② 보증금 14,000 + 월 60 | 10,000 | 720 ÷ 10,000 | `CONVERT`, 환산 전환율 연 **7.20%**. n=3,747 분포에서 p25 5.74%와 중앙값 7.38% 사이다 |

## 4. 화면 명세

### 4.0 Why — 화면은 숫자를 예쁘게 보여 주는 곳이 아니라 결정을 기록하는 곳이다

화면의 성공 조건은 "차트를 봤다"가 아니라 "마감 전에 행사 / 합의 / 무행동 중 하나를 명시적으로 선택해 기록했다"이다. 그래서 모든 화면은 마지막에 선택 버튼으로 끝난다.

### 4.1 공통 표시 규칙 (전 화면 강제)

| # | 규칙 | 구현 |
|---|---|---|
| DR1 | **표본 수를 항상 같은 문장 안에 쓴다.** `n` 없이 분포·중앙값·백분위를 렌더하는 컴포넌트를 금지한다 | 렌더 함수가 `n`을 필수 인자로 받는다. `n` 없이 호출하면 빌드가 깨지게 한다 |
| DR2 | **"미사용"이라는 단어를 쓰지 않는다.** "행사 기록 없음"으로 쓴다 | 문자열 린트: `미사용`, `미행사`(조문 인용 제외)를 금칙어로 등록 |
| DR3 | 기준일(asof)을 상단에 고정 표시 | 레이아웃 셸 |
| DR4 | 모수(분모)를 문장에 병기한다. 서울 전체 집계는 `anchors.scope` 문자열을 값 옆에 그대로 붙여 렌더한다 | `#anchor-scope` 한 곳에서 모수를 출력하고, 코호트 숫자에는 확장 단계 라벨을 붙인다 |
| DR5 | 데이터 한계 배너 4줄(§7.2)을 전 화면 하단에 고정 | 레이아웃 셸 |
| DR6 | 금액 표기: 1억 이상은 `N억 M,MMM만원`, 미만은 `M,MMM만원` | 공통 포매터 |

### 4.9 S7 — 환산 (월세 혼합 전용)

> 경계: 법정 전월세전환율과의 비교는 **이 화면에서 하지 않습니다.** 기준금리 데이터를 보유하지 않기 때문입니다. 위 7.20%는 **시장 데이터 역산값이지 법정 한도 판정이 아닙니다.**

## 5. 상태와 분기 (MECE)

### 5.1 Why — 조용히 통과하는 경로가 하나라도 있으면 사용자는 틀린 숫자를 믿는다

표본이 없거나, 주소를 못 찾거나, 데이터가 낡았거나, 외부 호출이 실패했을 때 화면이 아무 말도 하지 않으면 사용자는 그 화면을 정상 판정으로 읽는다. 모든 상태에 **사용자가 읽는 결말 문장**이 있어야 한다.

### 5.2 What — MECE의 기준

- **판정 모드(M-)**: 상호 배타적이다. 아래 우선순위 순서로 평가해 **정확히 하나**가 선택된다. 앞 모드가 걸리면 뒤 모드는 평가하지 않는다.
- **오버레이(O-)**: 모드와 독립적으로 각각 참/거짓이며 동시에 여러 개가 참일 수 있다. 각 오버레이는 모드가 낸 화면 위에 문장을 **추가**한다.

이 두 축으로 상태 공간이 빠짐없이·겹침없이 덮인다.

### 5.3 How — 모드 표 (우선순위 순, 위가 먼저)

## 6. AI가 맡는 두 단계

### 6.0 Why — AI를 두 곳에만 쓰는 이유

이 서비스의 판정은 전부 산술이므로 AI가 할 일이 없다. AI가 실제로 필요한 곳은 **판정의 앞뒤**뿐이다. 앞에서는 사람이 받은 문장("이번에 조금 올려야 할 것 같아요… 6억 4,800 정도로")을 계산이 먹을 수 있는 숫자로 바꾸고, 뒤에서는 코드가 낸 숫자를 그 사람의 상황 문장으로 다시 쓴다. 이 두 단계는 **판정을 만들지 않고 판정을 건드리지도 않는다.**

```
[사용자 문장] ──A1──▶ [구조화 JSON] ──사용자 확인 폼──▶ [계산 입력] ──코드 판정──▶ [판정 딕셔너리]
                                                                                    │
                                                        [문안] ◀──검증층──A2────────┘
```

**판정 딕셔너리는 A1의 출력이 아니라 사용자가 확인 버튼을 누른 값에서만 만들어진다.** 이것이 AI가 판정에 끼어들지 못하게 하는 1차 장치다.

### 6.0-A 면적 계약 (2026-09-19 추가) — 모델이 준 값이 통과해야 하는 관문

**Why**: 이전에는 `area_m2` 에 **형·범위 검사가 어디에도 없었다.** 모델이 준 값이 그대로 확인 줄의 `innerHTML` 로 갔고, CSP 를 뗀 환경에서는 스크립트가 실행됐다(실측). 범위를 벗어난 숫자(3000㎡)도 판정 입력 후보가 됐다. `docs/07-FINAL-REVIEW.md` F-12.

**What** — 모델 응답의 `area_m2` 는 다음을 전부 만족할 때만 값이고, 아니면 `null` 이다.

| 조건 | 값 |
|---|---|
| 타입 | `number` — **숫자 문자열(`"84.9"`)도 계약 위반이다.** 스키마가 `number` 라고 선언했고, 관대한 강제 변환은 형 검사가 아니다 |
| 유한성 | `Number.isFinite` |
| 범위 | 10 ≤ v ≤ 300 — **새로 만든 값이 아니라 원래 제품 범위다.** `dist/index.html:113` 의 `min="10" max="300"` 과 `app.js` `readInput` 의 `area >= 10 && area <= 300` 이 이전부터 같은 값을 쓰고 있었다. 계약은 그 범위를 모델 응답에도 적용한 것이다 |

**계약 밖이면 버린다 — 지어내지도, 0으로 만들지도 않는다.** 화면은 `—(그대로 둡니다)` 로 적고 입력 칸을 건드리지 않는다. 서버는 버린 사실을 응답 `missing` 에 `area_m2` 로 남긴다.

**금액과 달리 응답 전체를 버리지 않는다.** 면적은 사용자가 직접 넣을 수 있는 보조 값이고, 그것 하나 때문에 맞는 금액까지 수동 입력으로 보내면 손해가 더 크다.

**How** — 구현은 **두 런타임에 같은 값으로** 있다 — `functions/api/_llm.js` `areaM2`, `dist/assets/rules.js` `areaM2`. 두 구현이 갈라지면 `scripts/test_rules.mjs` 가 깨진다.

### 6.1 A1 — 조건 문장을 계산 입력으로 변환

**Why**: 사용자가 받은 것은 숫자 폼이 아니라 문자 한 통이다. 그 문장을 사람이 직접 폼에 옮기게 하면 단위(억/만원)와 월세 유무에서 오입력이 난다.

**What**: 자유 텍스트 → 금액. **판정은 하지 않는다.** 경로가 둘이고 **규칙이 먼저다.**

#### 6.1-0 규칙 파서 (`rules.js` `readAmounts`) — 먼저 시도한다

정형 문장은 산술로 읽힌다. 그런 문장까지 모델에 보내면 네트워크·키·비결정성이 붙고 **원문이 브라우저 밖으로 나간다.** 읽을 수 있으면 브라우저에서 읽고, 애매하면 읽지 않는다.

| 항목 | 내용 |
|---|---|
| 문법 | 보증금 **두 개**와 전세/월세 표시. 단위가 붙은 금액만 본다(`3억5천`·`6억`·`5천만`·`35,000만원`) |
| 방향 | 두 금액 사이에 `에서`·`인데`·`→` 같은 표시가 있어야 **종전 → 제시**로 읽는다. 없으면 읽지 않는다 |
| 하한 | 보증금 후보는 1,000만원 이상. 그 아래는 월세·관리비와 구분되지 않는다 |
| 범위 | 서버 `rangeCheck` 와 **같은 경계**(보증금 1~500,000만원, 월세 0~1,000만원, 인상률 −50~200%) |
| 읽지 않는 것 | 한글 수사(`구억육천`), 금액 하나뿐, 셋 이상, 관리비·주차·작년이 섞인 문장, 역순 |
| 실패 반환 | `NO_AMOUNT` · `AMBIGUOUS_ROLE` · `UNSUPPORTED_SYNTAX` · `OUT_OF_RANGE` → **A1 로 넘긴다** |

**합격 기준은 처리율이 아니라 조용한 오수락 0건이다.** 골든셋의 모든 문장에 대해 "정확한 값" 또는 "읽지 않음" 둘 중 하나여야 한다(`05-TEST.md` §4). 읽지 않는 것은 비용이지만 되돌릴 수 있고, 틀린 값을 조용히 채우는 것은 되돌릴 수 없다.

> 규칙 경로라고 방어선을 건너뛰지 않는다. 읽은 값은 언어 모델이 읽은 값과 **같은 자리**(`applyParsed`)를 지나고, 이후 입력 검증과 M-11 자릿수 되묻기를 똑같이 받는다. 신뢰도를 1.0 으로 박지 않는다 — 규칙 경로에는 신뢰도라는 개념이 없다.

#### 6.1-1 언어 모델 (`/api/parse`) — 규칙이 읽지 못한 문장만

**What**: 자유 텍스트 → 고정 스키마 JSON. **판정은 하지 않는다.**

**요청·응답 스키마의 정본은 `docs/04-API.md` §7.2 다.** 이 문서는 사본을 두지 않는다(`00-INDEX` §0). 구현은 `functions/api/parse.js` 이고 `scripts/test_verify.mjs` 가 응답 필드 12개를 해시 `e1f67371ab30be6d` 로 동결한다.

- 면적 값이 계약을 벗어나면 **응답을 버리지 않는다** — `area_m2` 만 `null` 로 내리고 `warnings` 에 남긴다(§6.0-A).

**이 절이 정하는 것은 실패가 화면에서 어떻게 끝나는가다.**

| 조건 | 오류 코드 | 화면 |

**확인 폼 (건너뛸 수 없다)**

### 6.2 A2 — 회신 문안의 인사말과 맺음말

**Why**: 코드가 낸 판정은 사람에게 보낼 문장이 아니다. 그런데 모델에게 **숫자 문장을 재서술시키면 숫자가 맞아도 라벨이 바뀐다** — 실측에서 코호트 전체 건수를 "행사 기록이 있는 건수"로, 5% 상한액을 "제시된 보증금"으로 바꿔 썼다. 숫자만 대조하는 검사로는 잡히지 않는 오류다.

그래서 검증을 늘리는 대신 **경로를 끊었다.** 모델은 판정 딕셔너리를 **보지 않는다.**

**What**: 선택(행사/합의/무행동)과 어조만 주고 **인사말 한두 문장, 맺음말 한두 문장**을 받는다. 숫자가 든 문장은 전부 브라우저의 코드가 만들어 그 사이에 넣는다.

**입력 스키마** (판정 딕셔너리도, 금액도, 허용 숫자 목록도 보내지 않는다)

```json
{ "choice": "행사 | 합의 | 무행동", "tone": "neutral | soft" }
```

**출력 스키마** (`strict: true` 구조화 출력)

```json
{ "opening": "1~2문장. 인사와 이 글을 보내는 이유만",
  "closing": "1~2문장. 회신 요청과 맺음 인사만" }
```

**응답**: `{ ok, frame, verified, source, reason }`. 검증층에 걸리면 `frame: null`, `verified: false`, `source: "template"`, `reason: numbers | forbidden | shape | upstream` 이다. **HTTP 상태는 언제나 200이고 실패는 본문으로 전달한다** — 클라이언트 분기를 한 곳에 모으기 위해서다.

**폴백**

| 조건 | 동작 |
|---|---|
| 타임아웃(15초) / 제공자 장애 / 키 없음 | **고정 인사말·맺음말**을 그대로 쓴다. 숫자 문장은 애초에 바뀌지 않으므로 문안 전체가 그대로 나온다 |
| 검증층 탈락 | 같은 고정 문구로 대체하고, 화면에 "문장 생성이 동작하지 않아 고정 인사말로 대신합니다"라고 적는다 |
| 사용자가 편집 | 편집된 문안을 그대로 쓴다. 이 서비스는 도달 여부와 효력을 판정하지 않는다 |

### 6.3 검증층 — AI 출력이 판정에 끼어들지 못하게 하는 장치

**Why**: AI가 판정을 못 하게 막는 것은 "프롬프트에 하지 말라고 쓰는 것"으로 보장되지 않는다. 구조와 검사로 막아야 한다.

**What**: 구조 하나와 검사 넷. **하나라도 걸리면 그 출력을 렌더하지 않는다.**

| # | 층 | 검사 내용 | 실패 시 |
|---|---|---|---|
| V1 | **구조 격리** | A1 출력은 화면의 확인 문장을 거쳐 사용자가 고칠 수 있는 입력 칸으로만 들어간다. A2 는 판정 딕셔너리를 **전달받지 않는다** — 읽을 수 없는 것은 바꿀 수도, 잘못 인용할 수도 없다 | 그 경로가 코드에 없다 |
| V2 | **숫자 금지** | A2 출력에 십진 숫자(`\p{Nd}`, 전각 포함)나 한글 금액 표현(`삼억원`, `만원`)이 있으면 위반. 조문 표기(`제6조의3`, `제1항`, `제8호`)의 숫자만 스캔에서 뺀다 | 전체 폐기 → 고정 문구 |
| V3 | **법 결론 금칙어** | `무효`, `위법`, `승소`, `권리가 있습니다`, `청구할 수 있습니다` 등. 표기 규칙 위반어(`미사용`, `미행사`)도 같은 목록에 둔다(DR2) | 전체 폐기 → 고정 문구 |
| V4 | **형태 검사** | `opening`·`closing` 이 비었거나 둘을 합쳐 600자를 넘으면 위반 | 전체 폐기 → 고정 문구 |
| V5 | **범위·신뢰도 게이트 (A1 전용)** | 금액이 1~500,000만원, 인상률 −50~200%, 월세 0~1,000만원 밖이면 폐기. `confidence < 0.7` 이거나 제시 보증금이 null 이면 폐기. **confidence 는 탈락에만 쓰고 통과 근거로 쓰지 않는다** — 실측에서 "구억육천만원"을 9,600으로 읽고도 0.98을 냈다 | `ok:false` + 수동 입력 폼. 거절된 값은 **입력 칸에 넣지 않는다** |

```js
const DIGIT = /\p{Nd}/u;
const KO_MONEY = /[일이삼사오육칠팔구십백천만억][억만천]?\s?원/;
const STATUTE = /제\s?\d+\s?조(?:의\s?\d+)?|제\s?\d+\s?항|제\s?\d+\s?호/g;

const hasDigits = (s) => {
  const t = String(s).replace(STATUTE, " ");
  return DIGIT.test(t) || KO_MONEY.test(t);
};
```

> **한글 수사를 전부 잡지는 않는다.** "이 글", "만나서"의 이·만까지 걸면 정상 인사말이 한 줄도 남지 않는다. 단위에 붙은 금액 표현만 본다. 화면 문구도 "숫자가 하나라도"가 아니라 **"숫자나 금액 표현"**이라고 쓴다 — 검사가 못 하는 일을 화면이 약속하지 않게 한다.

**AI가 절대 하지 않는 일 (명세로 고정)**

| 금지 | 이유 |
|---|---|
| 인상률·백분위·차액·표본 수를 계산하거나 추정한다 | 판정은 §3의 규칙만 낸다. A2 는 그 값을 받지도 않는다 |
| 표본이 없을 때 "대략 이 정도"라고 채운다 | M-08·M-09가 판정 불가로 끝낸다 |
| 실거주 주장의 진위, 특약의 효력, 권리 성립 여부를 말한다 | X1·X4, V3 |
| 사용자가 붙여넣은 원문을 저장한다 | §8.4. 로그에도 남기지 않는다 |

## 7. 고지 문안

### 7.1 Why — 법 조항을 화면에 띄우는 순간 사용자는 그것을 자문으로 읽을 수 있다

이 서비스는 조문을 인용하고 링크를 건다. 인용과 자문의 경계를 사용자가 스스로 긋게 두면 안 된다. 아래 3종은 **확정 문장**이고 임의로 고쳐 쓰지 않는다.

### 7.2 What — 법률 경계 3종 (확정 문장)

**L1. 자문 아님 — 전 화면 하단 고정**

> 이 서비스는 신고된 실거래 데이터로 **계약의 위치를 숫자로 보여 줍니다. 법률 자문을 하지 않습니다.** 법 조항은 원문과 출처를 그대로 보여 주고 링크만 겁니다. 판단이 필요하면 주택임대차분쟁조정위원회, 대한법률구조공단(☎132), 서울시 전월세보증금지원센터로 가세요.

**L2. 해석은 판정하지 않음 — 실거주 통보·계약서·특약 화면에 고정**

> 이 화면은 **실거주 주장의 진위, 계약서 문구와 특약의 효력, 권리 성립 여부를 판정하지 않습니다.** 관련 조문과 판례의 원문 링크를 드리고, 판단은 위 창구의 일로 남깁니다. 이 서비스가 만든 문안은 법률 문서가 아니며 도달 여부와 효력도 판정하지 않습니다.

**L3. 5% 상한의 적용 범위 — 판정 화면(S3)과 초과 차액이 나오는 모든 자리에 고정**

> **5% 상한은 갱신요구권을 행사한 갱신에 적용되고, 합의로 맺은 갱신에는 적용되지 않습니다.** 화면의 "초과 차액"은 **위법 금액이 아니라**, 갱신요구권을 행사했을 때의 상한과 제시받은 조건의 차이입니다.

### 7.3 How — 데이터 한계 배너 (4줄 + 조건부 2줄, 확정 문장)

**고정 4줄 — 전 화면 하단**

> ① 이 판정의 데이터 기준일은 **{asof}**입니다. `계약구분`이 비어 판정에서 빠지는 행이 **596,178행 중 13,104행(2.20%)** 있고, 신고와 정정이 반영되는 데 시간이 걸리므로 **최근 계약일수록 표본에서 빠질 수 있습니다.**
> ② 계산 범위는 **서울**입니다. 서울 숫자를 다른 지역에 적용하지 않습니다.
> ③ 원천이 단지 일련번호를 주는 유형은 **아파트뿐입니다.** 오피스텔·연립다세대·단독·다가구는 **596,178행 전부**가 비어 있어 같은 건물끼리 비교할 수 없고, **같은 법정동·비슷한 면적**으로 비교합니다.
> ④ 이 숫자들은 **신고된 결과이지 예측이 아닙니다.** 앞으로의 시세도, 협상의 결과도 예측하지 않습니다.

**조건부 2줄**

> ⑤ (R4를 쓰는 화면) **"행사 기록 없음"은 갱신 계약의 갱신요구권 칸이 비어 있다는 뜻입니다.** 법정 신고서 서식이 갱신 계약에 대해 행사/미행사 2지 택일만 두고 있고 데이터 생산기관도 빈 값을 미사용으로 집계하므로 미행사로 읽지만(근거 등급 B), 공표 데이터에 미기재가 섞여 있어도 데이터만으로는 분리되지 않습니다. 신규 계약 행은 이 칸이 100% 비어 있고 그 빈 값은 '해당 없음'이라 **이 집계에서 제외했습니다.**
> ⑥ (월세가 관련된 화면) 위 5% 초과 비율은 **월세가 0인 전세→전세 계약만**으로 계산했습니다. 월세를 환산해 포함하면 **35~46%** 사이에서 흔들립니다.

## 8. 비기능 요구

### 8.1 응답 시간 — Why: 마감 하루 전에 접속한 사람이 로딩을 기다리다 창을 닫으면 판정은 존재하지 않은 것과 같다

| 대상 | 목표 | 측정 | 초과 시 |
|---|---|---|---|
| 첫 화면(S1) 표시 | **1.5초 이내**(p95, 일반 모바일 회선) | 실사용 타이밍 | 스냅샷 사전 로드 축소 |
| 판정 실행(S1 → S3) | **1.0초 이내**(p95) | 서버 처리 시간 | 코호트 인덱스 추가 |
| 코호트 조회 1건 | **200ms 이내**(p95) | — | `(자치구, 법정동, 건물명, 면적구간)` 복합 인덱스 |
| A1 문장 변환 | **3초 타임아웃** | — | 직접 입력 폼으로 폴백(§6.1) |
| A2 문안 생성 | **5초 타임아웃** | — | 고정 템플릿 문안으로 폴백(§6.2) |

**설계 제약**: 판정 경로에 외부 네트워크 호출을 두지 않는다. 스냅샷은 배포 시점에 서버에 내장하거나 기동 시 1회 적재하고, 판정은 메모리·로컬 인덱스만 읽는다.

### 8.2 무장애 폴백 — Why: 이 서비스는 마감일에 가장 많이 쓰이므로, 그날 외부 의존이 하나라도 끊기면 안 된다

| 끊기는 것 | 사용자가 잃는 것 | 사용자가 유지하는 것 |
|---|---|---|
| AI 제공자 | 문장 붙여넣기 변환, 문안 개인화 | **판정 전부**, 직접 입력 폼, 고정 템플릿 문안 |
| 최신 스냅샷 | 최신성 | 직전 스냅샷으로 **같은 판정**(M-03 배너) |
| 공유 API | 공유 버튼 | 판정 결과 전부(O-04) |
| 네트워크 전체 | 새 판정 | 로컬에 저장된 이전 판정·선택 기록·날짜 알림 |

**원칙**: 어떤 외부 의존이 끊겨도 **§3의 7개 규칙은 전부 동작한다.** 규칙의 입력은 사용자 입력값과 내장 스냅샷뿐이다.

### 8.3 접근성 기본 — Why: 판정의 핵심이 숫자와 색이라 시각에만 의존하면 읽히지 않는다

| # | 요구 | 구현 |
|---|---|---|
| A1 | 색만으로 의미를 전달하지 않는다 | 초과/이내를 색과 **텍스트 라벨**로 동시에 표기 |
| A2 | 명도 대비 **4.5:1 이상**(본문), 3:1 이상(큰 글자·아이콘) | 디자인 토큰에 고정 |
| A3 | 모든 기능을 키보드만으로 완주할 수 있다 | 탭 순서 = 입력 순서, 포커스 링 유지, 모달 포커스 트랩 |
| A4 | 폼 입력마다 `<label>`과 오류 메시지가 프로그램적으로 연결된다 | `aria-describedby`, `aria-invalid` |
| A5 | 표와 수치 카드에 스크린리더용 캡션 | `<caption>`, 숫자에 단위를 텍스트로 병기("만원") |
| A6 | 본문 200% 확대에서 가로 스크롤 없이 읽힌다 | 반응형, 고정 픽셀 폭 금지 |
| A7 | 마감 배너는 애니메이션·자동 갱신으로 주의를 빼앗지 않는다 | 정적 배너, `prefers-reduced-motion` 존중 |

### 8.4 개인정보 미수집 — Why: 이 서비스는 개인정보 없이도 전부 동작하므로, 받지 않는 것이 가장 단순하고 가장 안전하다

| # | 원칙 | 구현 |
|---|---|---|
| P1 | **받지 않는다**: 이름, 연락처, 주민등록번호, 동·호수, 계약서 파일, 소득 정보, 로그인 계정 | 해당 입력 필드가 존재하지 않는다. 파일 업로드 기능이 없다 |
| P2 | **받는 것**: 자치구·법정동·건물명·전용면적·만기일·현 보증금·현 월세·제시 조건·(선택) 체결일·갱신권 기사용 여부·이사비 견적 | §2.2가 전부다 |
| P3 | 붙여넣은 임대인 메시지 원문은 **변환 직후 폐기한다** | A1 응답 반환 후 메모리에서 제거. 로그·DB·분석 도구 어디에도 남기지 않는다 |
| P4 | 통보 기록·선택 기록은 **브라우저 로컬에만** 저장한다 | localStorage. 내보내기는 사용자가 실행하고, 서버로 자동 전송하지 않는다 |
| P5 | 판정 요청은 처리 중에만 메모리에 두고 응답 후 버린다 | 요청 본문을 로그에 남기지 않는다. 접근 로그에서 쿼리스트링 제거 |
| P6 | 외부 공유 기능의 응답을 **저장하거나 AI에 넣지 않는다** | 공유는 결과 카드 전달 한 방향뿐 |
| P7 | 제3자 분석 스크립트를 넣지 않는다 | 사용 지표는 익명 카운터(화면 조회 수, 선택 분포)만, 개별 계약 값과 결합하지 않는다 |
| P8 | "입력 지우기" 한 번으로 로컬 데이터가 즉시 삭제된다 | 전 화면에서 접근 가능 |
