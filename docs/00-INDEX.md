## 1. 시간이 얼마나 있나

### 5분 — 이 제품이 무엇이고 무엇을 근거로 하는가

1. `README.md` §측정된 사실 — 숫자 표 두 개. **이 제품의 존재 이유가 그 표다.**
2. 배포본 https://gaengsin-baseline.pages.dev 에서 **"예시로 먼저 보기"** 한 번.
3. `README.md` §구현하면서 바꾼 결정 — 아홉 줄. 무엇을 왜 다르게 했는지.

### 15분 — 판정이 믿을 만한가

4. `01-PRD.md` §2 Why — 문제와 측정된 사실 D1~D8.
5. `02-SPEC.md` §3 산술 규칙 R1~R7 — **여기가 제품의 전부다.** 특히 §3.1의 정수 비교.
6. `05-TEST.md` §1 전략과 §3 데이터 게이트 — 틀린 숫자가 화면에 뜨는 경로를 어떻게 막는가.

### 60분 — 전부

7. `03-ARCHITECTURE.md` — 왜 이 구조인가, 데이터가 어디서 어디로 가는가.
8. `02-SPEC.md` §5 상태 표 — 화면이 끝나는 방식 전부(M-01~M-11, O-01~O-06).
9. `04-API.md` — 원천 API 를 직접 두드려 본 **측정 기록**. 재현하려면 이것만 있으면 된다.
10. `01-PRD.md` 부록 A — 제품을 정하기 전에 다른 원천으로 같은 질문을 물었던 기록.

## 4. 읽을 때 알아 두면 좋은 것

- **숫자는 전부 한 곳에서 온다.** `dist/data/anchors.json` 이다. 문서의 숫자가 그것과 다르면 `node scripts/test_anchors_docs.mjs` 가 깨진다. 문서를 믿기 전에 이 검사가 통과하는지 보면 된다.
- **모수가 값 옆에 붙어 있다.** "31.95%" 만 적힌 자리는 없다. 없으면 그것이 결함이다.
- **하나의 예외가 있다.** `01-PRD.md` 부록 A 는 제품을 정하기 전 다른 원천으로 잰 값이다. `<!-- 계열:서울시파일 -->` 로 감싸 두었고, 본문 숫자와 한 문장에 섞지 않는다.
- **"미확인" 과 "없다" 를 구분해 썼다.** 재현되지 않은 것은 재현되지 않았다고 적혀 있다(`05-TEST.md` §8).
