## 0. 정본 지도 — 어느 문서가 무엇의 주인인가

**규범적 정의는 한 문서에만 산다.** 다른 문서는 요약하고 링크한다. 같은 정의가 두 곳에서 관리되면 언젠가 갈라지고, 갈라진 것을 검사가 잡지 못한다.

**다섯 정본 문서**는 `01-PRD` · `02-SPEC` · `03-ARCHITECTURE` · `04-API` · `05-TEST` 다. 나머지(`00-INDEX`·`00-GLOSSARY`·`06-NIST-REVIEW`·`07-FINAL-REVIEW`·`STYLE`)는 **보조 문서**이고 정본을 만들지 않는다.

| 문서 | 답하는 질문 | **이 문서만이 정하는 것** | 근거 | 이어지는 곳 |
|---|---|---|---|---|
| `01-PRD.md` | 왜 만드나. 누구를 위해. 어디까지 하나 | 문제 정의, 대상 사용자와 맥락, **범위와 비범위**, 성공 지표, 제약과 가정, 열린 질문 | 앵커 D1~D8, 부록 A(다른 계열) | 범위 밖 요청은 `02-SPEC` 이 아니라 여기서 거절된다 |
| `02-SPEC.md` | 무엇을 하나. 화면이 어떻게 끝나나 | 입력 명세, **산술 규칙 R1~R7**, 화면 문장, **상태 분기 M-01~M-11 · O-01~O-06**, AI 두 단계의 책임과 검증층 규칙 | `dist/assets/rules.js`, `test_rules.mjs` | 구현은 `rules.js`, 기대값은 `05-TEST` §4 |
| `03-ARCHITECTURE.md` | 어떻게 구성하나. 무엇을 믿나 | 구성요소와 책임, 데이터 파이프라인 단계, 런타임 흐름, 배포 구성, **신뢰 경계와 보안**, 용량, **장애와 폴백**, 대안 기각 | 배포 후 실측 응답 | 함수의 계약은 `04-API` §7 |
| `04-API.md` | 원천이 실제로 무엇을 주나 | 외부 API 인증·응답 필드·측정 기록, **집계 자산 JSON 스키마**, **함수 인터페이스와 오류 코드**, 키·환경변수, 재현 절차 | 직접 호출한 응답 원문 | 스키마를 고치면 `build_assets.py` 와 `02-SPEC` §3 이 같이 바뀐다 |
| `05-TEST.md` | 무엇을 검사하나. 무엇이 아직 없나 | 검사 6종의 책임, **데이터 품질 게이트 8종**, **골든셋**, 분기 커버리지, **LLM 평가 증거와 그 한계**, 아직 없는 것 | `scripts/test_*.mjs`, `--selftest` | 게이트가 막으면 배포가 멈춘다 |

### 정본이 아닌 것

| 문서 | 무엇인가 | 주의 |
|---|---|---|
| `README.md` | **입구와 길잡이.** 제품 설명, 시나리오, 재현, 문서 안내 | 요구사항의 정본이 아니다. 여기와 정본이 다르면 정본이 맞다 |
| `00-GLOSSARY.md` | 용어와 **쓰지 않기로 한 말** | 표기 규칙의 정본이다(예: "미행사"가 아니라 "행사 기록 없음") |
| `06-NIST-REVIEW.md` | NIST 4종 참조 기준 136개 통제 대조 | **인증이 아니라 대조 기록.** 통제 판정의 정본이고 제품 명세를 만들지 않는다 |
| `07-FINAL-REVIEW.md` | 제출 직전 검토 기록 | 결함 목록의 정본. 제품 동작을 바꾸지 않는다 |
| `STYLE.md` | 문서 작성 규칙과 배포 전 확인 | 문체의 정본 |
| `../COPYRIGHT.md` | 저작권과 이용 조건 | **권리 방침의 정본.** 오픈소스로 공개하지 않는다 |

### 저장소 밖에 있는 것

| 무엇 | 어디 | 왜 |
|---|---|---|
| 아이디어 선정·데이터 리서치 원본, LLM 평가 기준·골든셋·실행 기록 | 로컬 `decisions/` — **`.gitignore` 안이라 저장소에 없다** | 경쟁 노출 방지로 로컬 보관. 문서가 이 경로를 인용할 때는 **저장소에서 열 수 없다**는 뜻이다 |
| 작업 일지·인수인계 | 로컬 `sessions/` — 같음 | 같음 |

**따라서 저장소만 받은 사람은 `decisions/` 를 열 수 없다.** 판단에 필요한 결론은 정본 문서 안에 옮겨 적혀 있어야 하고, 옮기지 못한 것은 "저장소에서 재현할 수 없다"고 적는다.

## 4. 읽을 때 알아 두면 좋은 것

- **숫자는 전부 한 곳에서 온다.** `dist/data/anchors.json` 이다. 문서의 숫자가 그것과 다르면 `node scripts/test_anchors_docs.mjs` 가 깨진다. 문서를 믿기 전에 이 검사가 통과하는지 보면 된다.
- **모수가 값 옆에 붙어 있다.** "32.46%" 만 적힌 자리는 없다. 없으면 그것이 결함이다.
- **하나의 예외가 있다.** `01-PRD.md` 부록 A 는 제품을 정하기 전 다른 원천으로 잰 값이다. `<!-- 계열:서울시파일 -->` 로 감싸 두었고, 본문 숫자와 한 문장에 섞지 않는다.
- **"미확인" 과 "없다" 를 구분해 썼다.** 재현되지 않은 것은 재현되지 않았다고 적혀 있다(`05-TEST.md` §8).
