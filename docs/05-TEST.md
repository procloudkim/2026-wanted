# 05. 테스트·검증 계획 — 갱신 기준선

작성일 2026-09-18 · 프레임워크 **Why → What → How**
근거: `decisions/01-idea-selection/round2-data-first/research/` 의 `05-handson-housing-price.md`(실측), `08-personas-journeys.md`(MECE 분기 36행), `09-field-semantics.md`(필드 의미), `scripts/quantify_renewal.py`(이미 도는 계산과 자체 검증)

## 1. 검증 전략 개요

### Why — 이 서비스에서 틀리면 사람이 돈을 잃는다
이 서비스의 출력은 "참고 차트"가 아니라 **사용자가 그날 회신에 쓰는 숫자**다. 인상률 백분위가 한 칸 틀리면 사용자는 1,800만원을 더 낸다. 그리고 `08 §6`이 기록한 대로 되돌릴 수 없는 순간(법정 마감·서명일)이 있어서, **틀린 판정을 나중에 고쳐도 사용자는 회수되지 않는다.** 그러므로 검증의 목표는 커버리지 숫자가 아니라 **"조용히 틀린 숫자가 화면에 뜨는 경로를 0으로 만드는 것"**이다.

### What — 보증하는 것 / 보증하지 않는 것

| | 항목 |
|---|---|
| **보증한다** | ① 같은 입력이면 항상 같은 판정이 나온다(결정론). ② 화면의 모든 숫자는 코드가 낸 값이고 LLM이 만든 값이 아니다. ③ 표본이 부족하거나 데이터가 없으면 **추정치 대신 "판정 불가" 결말**이 뜬다. ④ 신규 계약 행이 미행사 집단에 절대 섞이지 않는다. ⑤ 환산 가정이 바뀌면 숫자가 바뀐다는 사실이 화면과 테스트에 동시에 고정되어 있다. ⑥ 원천이 조용히 바뀌면 배포가 멈춘다. |
| **보증하지 않는다** | ⓐ 공표 데이터 자체의 진위 — 두 원천은 같은 RTMS 신고 원장에서 갈라져 나왔고 불일치가 0.044%다(`09 §4-C`). 교차 대조는 **독립 검증이 아니라 적재 오류 탐지**다. ⓑ 갱신 행 빈칸의 의미 — 미행사로 본다는 것은 **등급 B 판단**이지 확정이 아니다(`09 §1`). 테스트는 이 가정이 코드 전체에서 **일관되게** 쓰이는지만 본다. ⓒ 법적 효력·실거주 진정성·특약 유효성 — 판정하지 않으므로 테스트도 하지 않는다. ⓓ 미래 예측. |

### How — 5계층 + 게이트 2종
순수 계산 → 적재·정규화 → 집계 산출물 → 화면 문장 → LLM 출력, 이 순서로 아래에서 위로 막는다. 여기에 배포를 멈추는 **데이터 품질 게이트**(§4)와 원천 변화를 잡는 **회귀 감시**(§5)를 붙인다. 실행은 전부 `python3 <file> --selftest` 한 줄이고, CI는 이 명령들의 exit code만 본다.

## 2. 계층별 검증

### 2-1. ① 순수 계산 함수 (인상률·백분위·상한 차액·법정 기한·환산)

**Why.** `08 §5-1`이 확정했듯 **판정 계산은 6종뿐이고 전부 산술**이다. 산술이 틀리면 나머지 전부가 틀린다. 그리고 이 계층은 입력이 숫자 몇 개뿐이라 **고정 입력–고정 출력으로 완전히 봉인할 수 있는 유일한 계층**이다.

**What.** ① 인상률 `(현-종전)/종전` ② 백분위(정렬·인덱스 규칙) ③ 5% 상한 초과 판정과 초과 차액 `현 - 종전×1.05` ④ 법정 기한(만기 −6개월 / −2개월, **개월 단위**, 월말 보정) ⑤ 환산 전환율 `월세×12 ÷ 감액분`과 감액분 0의 분모 0 처리 ⑥ 파싱(콤마·공백·빈칸).

**How.** `rules.py --selftest` 안의 `assert`. 부동소수 비교는 전부 `abs(x-y) < 1e-9`로 쓴다 — `0.05` 경계가 판정을 가르므로 `==` 비교는 금지한다. **초과 판정은 `> CAP`이고 `>= CAP`가 아니다**(정확히 5.00%는 초과가 아니다). 골든셋(§3)이 이 계층의 회귀 테스트를 겸한다. 법정 기한은 `08 §6-7`이 남긴 미해결 — D-60 표기와 법정 마감이 하루 어긋나는 문제 — 를 **"개월 계산이 정답, D 표기는 보조"**로 고정하고 그 사실 자체를 assert한다.

### 2-2. ② 데이터 적재·정규화

**Why.** `05 §2.4`의 실측 — 서울 파일 단독·다가구 **25.22%(106,596행)**가 본번·부번·건물명·층 전부 결측이고, `05 §3-1`의 단지명 불일치 543건은 **공백·괄호 정규화로 추가 일치가 0건**이었다. 즉 "정규화하면 붙겠지"가 실측으로 반증된 구간이다. 게다가 2026-07-01 행정구역 개편으로 지자체명 표기가 섞였고, **별칭 정규화로 매칭률이 91.7% → 98.3%로 오른다.** 정규화는 성능 문제가 아니라 **판정 커버리지 문제**다.

**What.** 인코딩(CP949→UTF-8) · 헤더 오프셋(국토부 파일은 16행째가 헤더) · 필수 열 존재 · 숫자 파싱 · 주소 결측 행의 분류 · 지자체명/건물명 별칭 사전 적중 · 7키 중복 처리.

**How.** 원본 전수를 테스트에 쓰지 않는다. **손으로 만든 12행 fixture**에 위 사례를 하나씩 심는다(CP949 바이트 리터럴 1행, 헤더 앞 안내문 3행, 단독다가구 1행, 개편 전/후 지자체명 각 1행, 별칭 대상 건물명 2행, 7키 중복 2행). `load.py --selftest`가 이 fixture를 읽어 `assert len(rows)==N`, `assert 결측분류 == {...}`, `assert 별칭적중률 >= 0.95`를 확인한다. 전수 파일에 대한 검사는 테스트가 아니라 **게이트**(§4)에서 한다.

### 2-3. ③ 집계 산출물 (스냅샷)

**Why.** 화면은 원본 CSV를 읽지 않고 **미리 만든 스냅샷**을 읽는다. 스냅샷이 잘못 만들어지면 테스트가 전부 통과해도 화면은 틀린다. 그리고 이 계층이 **신규 계약 행 혼입**이 일어날 수 있는 유일한 지점이다.

**What.** 코호트 집계(자치구+법정동+건물명+전용면적 구간), 집단 분리(행사/미행사), 분포 통계(중앙값·p90·5% 초과 비율·초과 차액), 표본 수 n, 스냅샷 메타(기준일·행 수·환산 가정·원천 파일 해시).

**How.** ① **불변식 assert**를 집계 직후에 건다 — `assert 미행사_집단.계약구분 == {"갱신"}` (신규 행이 하나라도 섞이면 즉시 실패), `assert 미행사_n + 행사_n == 갱신_n`, `assert 모든 코호트.n >= 1`, `assert 초과차액 >= 0 for 초과건`. ② **환산 가정 고정 테스트**: 같은 fixture에 환산 배수만 바꿔(보증금만 / ×100 / ×240) 돌렸을 때 5% 초과 비율이 **서로 달라야** 한다고 assert한다. 실측에서 이 값은 35~46%로 움직인다(`09 §5-A`). 이 테스트의 목적은 값을 맞히는 게 아니라 **"가정이 바뀌면 숫자가 바뀐다"를 코드가 잊지 않게 하는 것**이고, 스냅샷 메타의 환산 가정 문자열이 화면 문장에 그대로 들어가는지까지 확인한다. ③ 스냅샷은 같은 입력에 대해 **바이트 동일**해야 한다(정렬 고정, dict 순서 고정) — `assert hash(snapshot1) == hash(snapshot2)`.

### 2-4. ④ 화면 문장

**Why.** `08`의 36개 분기는 전부 **"사용자가 읽는 결말 문장"**으로 끝난다. 결말 문장이 없으면 그 분기는 "조용한 통과"가 되고, 조용한 통과는 이 서비스가 없애려는 바로 그 실패다.

**What.** ① 모든 분기가 결말 문장을 렌더한다(빈 화면·스피너 정지 금지). ② 표본 수 n이 화면에 그대로 찍힌다. ③ 코호트를 넓혔으면 **넓혔다는 사실**이 문장에 있다. ④ 데이터 기준일 배너가 항상 있다. ⑤ 판정 불가일 때 숫자 대신 "판정하지 않습니다"가 뜬다.

**How.** 브라우저를 띄우지 않는다. 화면 함수를 **"판정 딕셔너리 → 문장 문자열" 순수 함수**로 두고 문자열을 assert한다. 분기 테스트(§6)가 이 계층의 본체다. 체크는 `assert "판정하지 않습니다" in s`, `assert f"{n}건" in s`, `assert 기준일 in s` 수준의 부분 문자열 확인으로 충분하다 — 문구 전문을 고정하면 문구를 다듬을 때마다 테스트가 깨진다.

### 2-5. ⑤ LLM 출력 검증층

**Why.** LLM은 판정하지 않는다. 그런데 **문장을 쓰는 순간 숫자를 쓸 수 있다.** 이 계층은 "쓰지 않기로 했다"를 코드로 강제하는 자리다. 상세는 §7.

**What.** 구조화 출력 스키마, 숫자 문자열 일치, 법 결론 금칙어, 입력에 없는 고유명사·날짜 폐기, 폴백.

**How.** LLM을 호출하지 않는다. **미리 저장한 응답 문자열 12개**(정상 3 + 위반 9)를 스텁으로 넣어 검증층 함수만 돌린다. 키 없이 돌고, 매번 같은 결과가 나온다.

## 3. 골든셋 — 손으로 만든 고정 입력과 기대 출력

**Why.** 실측 파일은 매일 바뀌므로 회귀 기준이 될 수 없다. 기준은 **변하지 않는 손으로 쓴 행**이어야 한다.
**What.** 26건. 전부 `tests/golden/fixture.csv`(입력) + `tests/golden/expected.json`(기대)에 있다.
**How.** `tests/run.py`가 fixture를 계산 경로 전체에 통과시키고 expected와 `assert`로 대조한다. 한 건이라도 어긋나면 exit 1.

## 4. 데이터 품질 게이트

**Why.** 스냅샷은 하루 한 번 새로 만들어진다. 원천이 망가진 날 **자동으로 화면에 반영되는 것**이 이 서비스의 가장 큰 단일 위험이다. 테스트는 코드를 지키고, 게이트는 데이터를 지킨다.

**What / How.** 스냅샷 생성 직후 `gate.py`가 아래를 계산해 `HARD` 하나라도 미달이면 **스냅샷 승격을 중단**한다(직전 스냅샷 유지 + 배너, `criteria G1`). `SOFT` 미달은 배포는 하되 화면에 사실을 표시하고 로그에 남긴다.

| # | 기준 | 임계값 | 실측 기준선 | 등급 |
|---|---|---|---|---|
| Q1 | 필수 열 존재 | 11개 전부 | — | **HARD** |
| Q2 | 갱신 행의 종전 보증금 결측률 | ≤ 0.5% | 0.00% (73,896행 기준) | **HARD** |
| Q3 | 갱신 행의 갱신요구권 **양성 토큰 채움률** | ≥ 25%, 전 스냅샷 대비 **−5%p 이내** | 42.84%(아파트 2026) / 49.02%(2025) / 31.55%(연립) | **HARD** |
| Q4 | `계약구분` 공란률 | ≤ 10% | 2.32%(2026) / 8.45%(2025) | SOFT(≤10%) · **HARD**(>15%) |
| Q5 | 단독·다가구 주소 결측률 | 20~30% 범위 밖이면 경보 | 25.22% | SOFT |
| Q6 | 7키 중복률 | ≤ 15% | 9.66%(국토부) / 5.67%(서울) | SOFT |
| Q7 | 완전 동일행 중복 | ≤ 0.1% | — | **HARD** |
| Q8 | 기준일 신선도 — 최신 계약일 | 오늘 − 14일 이내 | 서울 파일 2026-09-16 | **HARD** |
| Q9 | 스냅샷 생성일 | 오늘 − 7일 이내 | — | SOFT |
| Q10 | **별칭 정규화 후 매칭률** | ≥ 95% | 정규화 전 91.7% → 후 98.3% | **HARD** |
| Q11 | 두 원천 교차 불일치율 | ≤ 0.5% | 0.044% | **HARD**(적재 오류 탐지용) |
| Q12 | 총 행 수 변동 | 직전 대비 ±20% 이내 | — | **HARD** |
| Q13 | 갱신요구권 값 도메인 | `{사용, -}` / `{○, ""}` 밖의 토큰 0개 | — | **HARD** |

**배포 중단 규칙.** HARD 미달 → 승격 중단, 직전 스냅샷으로 서비스 계속, 화면 상단에 "데이터 기준일 YYYY-MM-DD(갱신 보류 중)" 배너. **판정 기능은 멈추지 않는다** — 멈추는 것은 갱신뿐이다. SOFT 미달 → 승격하되 해당 사실을 한 문장으로 화면에 표시. Q11은 **일치율이 높아야 통과**하는 항목이고, 이것은 데이터가 참임을 뜻하지 않는다. 같은 원천이므로 원래 일치하는 게 정상이고, **불일치가 튀면 우리 적재가 깨진 것**이다.

## 5. 회귀 감시 — 원천이 조용히 바뀌는 경우

**Why.** 공표 데이터는 예고 없이 바뀐다. 초기에 국토부 API 표본에서 공백을 관측했지만 2026-09-18 국토부 4종 API 실측(360회 호출, 149,651행)으로 그 행이 **신규 계약**이었음이 확인됐다(신규는 정의상 공백). **갱신 행 기준선은 종전 보증금 채움률 99.56~99.98%**다. 열이 사라지거나 값이 비어도 파이프라인은 에러 없이 통과하고 **화면의 숫자만 조용히 틀려진다.** 이것이 이 서비스에서 가장 탐지하기 어려운 고장 유형이다.

**What / How.**

| 고장 유형 | 탐지 방법 | 반응 |
|---|---|---|
| **필드 사라짐/이름 변경** | 헤더 집합을 직전 스냅샷과 diff. 필수 11열 누락 또는 신규 열 등장 | HARD 중단 + 헤더 diff를 로그에 그대로 출력 |
| **채움률 급락** | 갱신 행의 종전 보증금·갱신요구권 채움률을 스냅샷마다 시계열로 적재. 기준선 99.56~99.98% 대비 −5%p, 30일 이동중앙값 대비 −10%p | HARD 중단. 신규 행은 정의상 공백이므로 **갱신 행만** 분모로 센다 |
| **행정구역명 변경** | 2026-07-01 개편으로 지자체명 표기가 섞였다. 별칭 사전에 **없는 지자체명 토큰 목록**을 매 스냅샷 출력하고, 별칭 적용 후 매칭률(Q10)을 추적 | 신규 토큰 발견 시 SOFT 경보 + 별칭 사전 갱신 과제 생성. 매칭률 95% 미만이면 HARD |
| **갱신 주기 지연** | 최신 계약일이 **2회 연속 동일**하면 원천 정체로 본다 | SOFT — "데이터 갱신 지연" 배너(분기 B7/C7의 결말 문장과 동일) |
| **값 도메인 변경** | 갱신요구권·계약구분 토큰 집합 diff (Q13) | HARD 중단 |
| **의미 변경(가장 위험)** | 미행사 집단의 5% 초과 비율이 전 스냅샷 대비 ±10%p 이상 이동 | HARD 중단 후 **사람이 원인을 확인**. 시장이 그만큼 움직였을 수도 있고 인코딩이 바뀌었을 수도 있는데, 코드는 둘을 구분하지 못한다 |
| **API 표본 공백** | 국토부 OpenAPI를 하루 1회 **20건만** 조회해 갱신요구권·종전 보증금 공백률을 기록(키 필요, §9-B) | 공백률이 파일 기준선과 10%p 이상 다르면 SOFT 경보 |

## 6. 분기 테스트

**Why.** `08`의 36개 분기는 이미 "입력 조건 → 화면 결말"로 쓰여 있다. **그대로 테스트 케이스다.** 새로 설계할 것이 없다.
**What.** 여정 A/B/C에서 서로 다른 코드 경로를 타는 14개를 고른다(나머지는 이 14개의 결말 문장을 재사용한다).
**How.** `tests/run.py`가 각 행의 입력 딕셔너리를 판정 함수 → 문장 함수에 통과시키고, 기대 결말의 **핵심 토큰**이 출력 문자열에 있는지 assert한다. 판정 숫자가 뜨면 안 되는 분기는 `assert not re.search(r"상위 \d", s)`처럼 **없어야 할 것**도 확인한다.

| # | 분기 | 입력 조건 | 기대되는 사용자 화면 결말 (assert 토큰) |
|---|---|---|---|
| T1 | 정상 판정 | 아파트, 전세→전세, 코호트 n≥3 | 백분위 + `n건` + 기준일 배너 |
| T2 | 코호트 표본 부족 (A-B1) | n < 3 | "백분위 판정을 하지 않습니다" + 법정동 확장 + **"넓혔다"** 표시 + `77.8%` |
| T3 | 표본 0건 (A-B10) | 필터 통과 0행 | "판정 불가" + 완화 단계별 건수 + **추정치 없음** |
| T4 | 단독·다가구 (A-B2) | 건물용도 단독다가구 또는 주소 결측 | "찾을 수 없습니다" + `25.22%` + **인상률 백분위 미표시** |
| T5 | 월세 혼합 (A-B3) | 종전 또는 현 월세 > 0 | 보증금 비교 화면 **잠금** + 환산 경로 이동 + 잠근 이유 표시 |
| T6 | 서울 밖 (A-B4) | 자치구 ∉ 서울 25개 | 분포 숫자 **미표시** + 기한·문안·알림은 동작 |
| T7 | 갱신권 기 사용 (A-B5) | 사용자 입력 "행사함" | 1회 한정 안내 + 기준선을 미행사 분포로 교체 + **입력 의존 고지** |
| T8 | 실거주 주장 (A-B6) | 메시지에서 실거주 표현 감지 | **진위 판정 없음** + 원문 링크 + 기록 체크리스트 이동 |
| T9 | 데이터 지연 (A-B7) | 기준일 경과 / 공란률 상승 | 기준일 명시 + "최근 계약은 표본에서 빠질 수 있습니다" |
| T10 | 무행동 마감 통과 (A-B8) | 마감 경과 + 선택 기록 없음 | 두 경로(합의·묵시적) 병렬 표시 + **침묵이 조용히 통과하지 않음** |
| T11 | 건물명 별칭 (A-B9) | 입력 건물명 미매칭 | 후보 3개 + `543건` + **"직접 고르지 않으면 판정하지 않습니다"** |
| T12 | 소스 장애 (A-B11) | 스냅샷 로드 실패 | 직전 스냅샷으로 **같은 판정** + 폴백 배너 |
| T13 | 순증 (C9) | 감액분 0 & 월세 > 0 | "전환율을 계산할 수 없습니다(분모 0)" + 연 부담률만 + **6.27% 분포와 비교 안 함** |
| T14 | 오피스텔·기타 (C12) | 용도 ∉ {아파트, 연립다세대} | 분포 판정 **없음** + 산술·기한만 제공 |

## 7. LLM 출력 검증

**Why.** `08 §5-1 M10`이 못 박았다 — 판정은 코드가 하고 AI는 문장만 쓴다. 그런데 문장을 쓰는 모델은 **숫자를 만들 수 있고, 법 결론을 쓸 수 있고, 사용자가 붙여넣은 임대인 메시지 안의 지시를 따를 수 있다.** 이 세 가지가 실제 위험이고, 셋 다 테스트 가능하다.

**What / How** — 검증층 함수 4개, 전부 LLM 없이 스텁 응답으로 테스트한다.

| 검사 | 방법 | 실패 시 | 테스트 케이스 |
|---|---|---|---|
| **① 구조화 출력 스키마** | `json.loads` → 키 집합·타입·enum 확인. 스키마 밖 키는 **버린다**(무시가 아니라 제거) | 폴백 | 정상 1 / 키 누락 1 / 타입 오류 1 / 추가 키 1 / JSON 아님 1 |
| **② 숫자 임의 생성 차단** | 출력 문장에서 숫자 토큰을 정규식으로 전부 추출 → **코드 산출 딕셔너리의 값 문자열 집합**에 없는 토큰이 하나라도 있으면 **그 문장 폐기**, 템플릿 문장으로 대체 | 문장 단위 폐기 | 코드값만 쓴 문장(통과) / `5.2%`를 지어낸 문장(폐기) / 코드값을 반올림한 `5%`(폐기 — 반올림도 생성이다) |
| **③ 판정 문장 주입 차단** | 법 결론 금칙어 필터: 위법·불법·무효·승소·패소·청구하세요·한도 위반·가능합니다·해도 됩니다 | 문장 폐기 | 금칙어 포함 3종 |
| **④ 입력 밖 사실 차단** | 사용자 입력 필드 값 집합에 없는 **고유명사·날짜·금액**이 등장하면 폐기 | 문장 폐기 | 없는 단지명 1 / 없는 날짜 1 |
| **⑤ 프롬프트 주입** | 붙여넣은 임대인 메시지를 **데이터로만** 취급. 메시지에 "위 지시를 무시하고…"류가 들어와도 출력은 스키마를 벗어날 수 없고, ②~④가 다시 걸러낸다 | 스키마 단계에서 차단 | 주입 문자열 2종 |
| **⑥ 폴백 경로** | LLM 호출 실패·타임아웃·스키마 불통과 → **템플릿 문장**으로 렌더. **판정 숫자는 그대로 나온다** | — | 예외 발생 스텁 / 타임아웃 스텁 / 빈 응답 스텁 → 세 경우 모두 `assert 판정숫자 in 화면` |

**핵심 assert 하나**: `assert 화면숫자집합 ⊆ 코드산출숫자집합`. 이 한 줄이 "LLM은 판정하지 않는다"의 기계적 정의다.
**카카오 경계**: 카카오는 공유 한 곳뿐이다. 카카오 응답이 저장소나 LLM 입력에 도달하지 않는 것을 **소스 grep 기반 assert**로 확인한다(카카오 응답 변수가 저장·프롬프트 함수에 전달되지 않는다). 카카오가 끊기면 공유 버튼만 사라지고 판정은 그대로다.

## 8. 수동 확인 체크리스트 (배포 전, 사람이 눈으로)

자동화로 잡히지 않는 것만 남긴다. 10분 안에 끝난다.

- [ ] 로그인 없이 URL을 열어 **만기일 하나만 입력**해도 법정 기한 타임라인이 나온다.
- [ ] 화면 상단 **데이터 기준일**이 오늘 기준으로 말이 되는 날짜다.
- [ ] 데이터 한계 배너 4줄(기준일 / 서울 중심 / 단독·다가구 25.22% / **신고된 결과이지 예측이 아님**)이 보인다.
- [ ] 미행사 집단 라벨이 **"행사 기록이 없는 갱신 계약"**이다. "미사용"이라는 단어가 화면에 없다.
- [ ] **환산 가정 문장**(월세를 어떻게 환산했는지)이 숫자 옆에 붙어 있다.
- [ ] 표본 수 `n`이 판정 문장 안에 그대로 찍혀 있다.
- [ ] 표본 부족 케이스를 일부러 입력했을 때 숫자가 아니라 **"판정하지 않습니다"**가 나온다.
- [ ] 월세를 입력하면 보증금 백분위 화면이 **잠기고 그 이유가 보인다**.
- [ ] 모바일 폭에서 표가 가로로 넘치지 않고, 숫자가 잘리지 않는다.
- [ ] 개인정보 입력 칸이 없다 — 이름·연락처·동·호수·계약서 업로드 **전부 없다**.
- [ ] 법률 경계 문구와 창구(분쟁조정위 / ☎132 / 전월세보증금지원센터) 링크가 살아 있다.
- [ ] 스냅샷을 일부러 망가뜨렸을 때 **직전 스냅샷 + 폴백 배너**로 같은 판정이 나온다.

## 9. 재현 절차

### A. 키 없이 도는 것 (CI 기본, 네트워크 0)


전부 표준 라이브러리만 쓴다(`csv`, `json`, `re`, `datetime`, `hashlib`, `unittest` 불필요). 실패는 `AssertionError`와 exit code 1로 나온다. **`tests/run.py` 한 줄만 돌려도 골든셋과 분기는 다 본다.**

### B. 네트워크가 필요한 것 (키는 여전히 불필요)

- 원천 재다운로드: `POST rt.molit.go.kr/pt/xls/ptXlsCSVDown.do`(국토부 실거래가, CP949) / `POST datafile.seoul.go.kr/.../download.do`(서울 OA-21276). **인증키 없이 받힌다.** 주의: 서울 엔드포인트의 `strWhere`는 무시되므로 과거 연도를 못 받는다.
- 전수 게이트 실행: `python3 data/gate.py --source <csv>` → §4의 Q1~Q13을 실제 파일에 대해 계산. **CI에 넣지 않는다**(수십 MB 다운로드). 스냅샷 생성 파이프라인에서만 돈다.

### C. 키가 필요한 것

- **국토부 OpenAPI 표본 조회**(`getRTMSDataSvcAptRent`, data.go.kr 서비스키): §5의 "API 표본 공백" 감시 전용. **하루 20건**만 조회한다. 키가 없으면 이 감시 하나만 건너뛰고 나머지는 전부 돈다.
- **카카오 공유**(앱키): 공유 버튼 동작 확인용. 판정과 무관하므로 테스트 대상이 아니고, 카카오 응답을 저장하거나 LLM에 넣지 않는다는 것만 §7의 grep assert로 확인한다.

**키 없이 도는 것만으로 §2의 5계층 전부와 §3·§6·§7이 검증된다.** 키가 필요한 것은 §5의 감시 항목 하나뿐이다.

## 10. 테스트가 잡지 못하는 것 (정직하게 남긴다)

1. **빈칸=미행사 가정이 틀렸을 경우.** 등급 B 판단이고 데이터로는 확정할 수 없다. 테스트는 이 가정의 **일관된 적용**만 보증한다. 확정에는 기관 문의가 필요하다(`09 §6`).
2. **교차 대조는 독립 검증이 아니다.** 두 원천이 같은 신고 원장에서 나와 불일치가 0.044%다. 둘 다 같은 방향으로 틀리면 우리는 모른다.
3. **2020-12-10 이전 체결 계약의 1개월 전 기준** 분기가 설계에 없다(`08 §6-7`). 골든셋 G22·G23은 현행 기준만 덮는다.
4. **주택 유형별 코호트 가용률은 2026-09-18 측정됐다.** 아파트 65.11%, 오피스텔 41.77%, 단독·다가구 39.09%, 연립다세대 9.02%(건물명 기준). 연립다세대는 건물명 코호트가 성립하지 않아 읍면동+면적 구간으로 내려야 하며, 이 변경의 신뢰도 손실은 아직 검증하지 않았다.
