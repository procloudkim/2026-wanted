## 1. 전략

### Why — 틀리면 사람이 돈을 잃는다

이 서비스의 출력은 참고 차트가 아니라 **사용자가 그날 회신에 쓰는 숫자**다. 백분위가 한 칸 틀리면 사용자는 수백만원을 더 낸다. 그리고 되돌릴 수 없는 순간(법정 마감·서명일)이 있어서 **틀린 판정을 나중에 고쳐도 사용자는 회수되지 않는다.**

그래서 검증의 목표는 커버리지 숫자가 아니라 **"조용히 틀린 숫자가 화면에 뜨는 경로를 0으로 만드는 것"**이다. 조용한 경로는 세 가지다 — ① 산술이 틀린다 ② 원천이 바뀌었는데 파이프라인이 에러 없이 통과한다 ③ 화면·문서의 숫자가 스냅샷과 어긋난다. 검사도 셋이다.

### What — 보증하는 것과 보증하지 않는 것

| | 항목 |
|---|---|
| **보증한다** | ① 같은 입력이면 항상 같은 판정이 나온다(결정론). ② 화면의 숫자는 전부 코드가 낸 값이고 언어 모델이 만든 값이 아니다. ③ 표본이 부족하면 추정치 대신 "판정 불가" 결말이 뜬다. ④ 신규 계약 행이 갱신 집단에 섞이지 않는다. ⑤ 원천의 채움률이 무너지면 배포가 멈춘다. ⑥ 문서·OG 메타의 수치가 스냅샷과 어긋나면 검사가 깨진다. |
| **보증하지 않는다** | ⓐ 공표 데이터 자체의 진위. ⓑ 갱신 행 빈칸의 의미 — 미행사로 본다는 것은 **근거 등급 B 판단**이지 확정이 아니다. 검사는 이 가정이 코드 전체에서 일관되게 쓰이는지만 본다. ⓒ 법적 효력·실거주 진정성·특약 유효성 — 판정하지 않으므로 검사하지도 않는다. ⓓ 미래 예측. ⓔ 브라우저 렌더 결과 — §7의 사람 확인으로 남긴다. |

### How — 검사 6종, 전부 키·네트워크 없이

```
./scripts/test_all.sh
├─ python3 scripts/build_assets.py --selftest   ② 수집·집계 (손으로 쓴 XML 픽스처 6행)
├─ node scripts/test_rules.mjs                  ① 판정 산술·문장 읽기 30건
├─ node scripts/test_verify.mjs                 ⑤ LLM 검증층·오리진 경계 8건
├─ node scripts/test_contrast.mjs               ④ 색 대비 36쌍
├─ node scripts/test_anchors_docs.mjs           ③ 스냅샷↔문서·메타 대조
└─ node scripts/test_source.mjs                  ⑥ 소스 금지 패턴 17건
```

실패는 `AssertionError` 와 exit 1 로 나온다. `set -e` 가 종료 코드를 받아 첫 실패에서 멈춘다. 새 프레임워크를 들이지 않았다 — 표준 라이브러리 `assert` 와 작은 스크립트뿐이고 `package.json` 이 없다.

## 2. 계층별 검증

### 2-1. ① 판정 산술 — `node scripts/test_rules.mjs`

**Why.** 판정은 산술 7종뿐이고 전부 순수 함수다. 산술이 틀리면 나머지 전부가 틀린다. 그리고 입력이 숫자 몇 개뿐이라 **고정 입력–고정 출력으로 완전히 봉인할 수 있는 유일한 계층**이다.

**What.** `dist/assets/rules.js` 의 R1~R7 과 표시 포맷, 폴백 사다리, 금액 입력 파싱, **붙여넣은 문장 읽기**, 평가셋 라우팅 동결. 30건.

**How.** 기대값은 02-SPEC §3의 검증 표를 그대로 옮긴 것이다. 표가 바뀌면 여기가 먼저 깨져야 한다. 특히 못 박아 둔 것 넷:

| 고정한 것 | 왜 |
|---|---|
| 반올림은 **사사오입**(`floor(x+0.5)`) | 파이썬 `round` 는 은행원 반올림이다. 그대로 두면 빌드와 브라우저가 같은 데이터에서 다른 분위수를 낸다 |
| 5% 동치·초과는 **정수 교차 곱** | 실수 비교를 쓰면 정확히 +5.00%인 계약이 초과로 샌다. 전세→전세 갱신의 26.51%가 그 무리다 |
| 코호트의 5% 초과 건수는 벡터가 아니라 **원본 행의 정수 비교 결과** | 인상률을 0.01%p 정수로 접으면 5.0026%가 5.00%로 내려앉는다. 실측에서 행사 기록 있는 쪽의 초과가 0.37% → 0.01%로 바뀌었다 |
| 금액 칸은 **만원 단위 정수 표기만** | 소수를 받으면 위 정수 비교가 뒤집힌다. `1e5`·`0x10` 은 사용자가 친 금액이 아니다 |
| 문장 읽기는 **정확히 읽거나 읽지 않거나** | 규칙 파서가 틀린 값을 채우면 되돌릴 수 없다. 읽지 않으면 언어 모델로 넘어가 방어선을 한 번 더 지난다 |

### 2-2. ② 수집·집계 — `python3 scripts/build_assets.py --selftest`

**Why.** 화면은 원본을 읽지 않고 **미리 만든 스냅샷**을 읽는다. 스냅샷이 잘못 만들어지면 다른 검사가 전부 통과해도 화면은 틀린다. 그리고 이 계층이 **신규 계약 행 혼입**이 일어날 수 있는 유일한 지점이다.

**What.** XML 파싱 → 전세→전세 갱신 판별 → 면적 구간 → 코호트 키 → 분포 집계 → 앵커 → 샤드.

**How.** 손으로 쓴 XML 픽스처 6행에 실패 사례를 하나씩 심었다. 네트워크가 없다.

| 픽스처 행 | 지키는 규칙 |
|---|---|
| 종전 월세가 **공백**인 갱신 | 종전이 전세면 종전 월세는 0이 아니라 공백으로 온다. 숫자로 읽으면 표본이 통째로 사라진다 |
| `계약구분 = 신규` | 신규 행은 갱신요구권 칸이 100% 비어 있다. 집계에 들어가면 "행사 기록 없음"이 오염된다 |
| 종전 **4만원** → 48,500만원 (+1,212,400%) | 자릿수 사고로 보고 버린다(−90~300% 밖). 평균을 쓰지 않는 이유이기도 하다 |
| 현·종전 둘 다 월세 | 전세→전세가 아니다. 보증금 단독 비교가 성립하지 않는다 |
| 정확히 +5.00% 1건, 초과 2건 | `ro/no/rt/nt` 가 정수 비교 결과를 그대로 싣는지 |

### 2-3. ③ 스냅샷 ↔ 문서·메타 — `node scripts/test_anchors_docs.mjs`

**Why.** 수치의 단일 출처는 `dist/data/anchors.json` 이고 화면 본문은 전부 거기서 채운다. 그런데 **문서와 OG 메타만 손으로 적혀 있다.** 데이터를 다시 모으면 화면은 따라가고 문서만 조용히 낡는다. 실제로 이 저장소에는 한때 세 계열의 숫자가 동시에 살아 있었다.

**What / How.** 재계산하지 않는다. 스냅샷 값을 `rules.js` 와 같은 포맷으로 만들어 **전사됐는지만** 본다.

| 검사 | 내용 |
|---|---|
| 전사 | README·01-PRD·02-SPEC·03-ARCHITECTURE·05-TEST 와 `index.html` 의 OG 메타가 앵커 값을 그 표기로 담고 있는가. 스냅샷이 바뀌면 새 값이 문서에 없어서 깨진다 |
| 금지 | 초기 탐색 계열(서울시 파일)과 중간 표본의 값이 현 계열 문장에 남아 있지 않은가. 의도한 인용은 `<!-- 계열:서울시파일 -->` 로 감싼다(01-PRD 부록 A) |
| 구조 | 화면이 `anchors.scope`(모수 문자열)를 그대로 출력하는가(02-SPEC DR4). 분포 상수가 `rules.js` 에 다시 박히지 않았는가 |

`docs/04-API.md` 는 대상이 아니다. 그 문서는 API 를 직접 두드려 본 **측정 기록**이고, 거기 적힌 숫자는 화면에 쓰는 값이 아니라 재현했을 때 나와야 하는 기대값이다.

### 2-4. ④ 화면 — `node scripts/test_contrast.mjs` + 사람 확인

**Why.** 다크모드는 스크린샷으로 확인되지 않는다. 토큰 하나를 바꾸면 조용히 읽을 수 없는 조합이 생긴다.

**What / How.** `app.css` 의 색 토큰을 직접 읽어 대비를 계산한다. 본문 4.5:1, 큰 글자·경계 3:1. 라이트·다크 각 18쌍. `body` 에 명시적 배경이 있는지, 두 테마에 같은 토큰이 다 있는지도 본다.

**브라우저를 띄우는 검사는 없다.** 렌더 결과는 §7의 사람 확인으로 남긴다 — 자동화하지 않았다는 사실을 숨기지 않는다.

### 2-6. ⑥ 소스 금지 패턴 — `node scripts/test_source.mjs`

**Why.** 정적 분석이 0건이었다(06-NIST-REVIEW §4-D). 린터를 들이려면 npm 의존성이 생기는데 **`package.json` 이 없는 것이 이 저장소의 설계**다. 그래서 넓은 분석 대신 **좁은 금지 목록**을 둔다.

**What / How.** 문자열 검사로 **정확히 잡히는 것만** 잡는다. 데이터 흐름을 따라가지 않는다.

| 검사 | 지키는 것 |
|---|---|
| `eval`·`new Function`·`document.write` 0건 | 실행 경로에 문자열을 넣지 않는다 |
| `innerHTML` 자리 **수를 고정**(26) | 안전을 자동으로 증명할 수는 없다. 자리가 늘면 사람이 그 자리를 본다 — 여기서 할 수 있는 정직한 최대치다 |
| 키 형태 문자열 0건 | `sk-…`, 40자 이상 16진, 원천 키 하드코딩 |
| 배포물에 `http://` 0건 | 혼합 콘텐츠. SVG 네임스페이스는 가져오는 주소가 아니라 식별자라 제외 |
| `target="_blank"` 에 `rel="noopener"` | 창 참조 유출 |
| **배포물이 불러오는 자산이 전부 우리 것인가** | `<link>`·`<script>`·`<img>`·CSS `url()` 에 외부 오리진 0. CSP 의 `style-src`·`font-src` 도 `'self'`. 사용자가 눌러서 나가는 `<a href>` 는 대상이 아니다 |
| **함수의 로그 호출 형태 고정** | 우리 줄은 `{ev, code, ms}` 말고는 못 나간다. "로그에 남기지 않는다"는 약속이 주석이 아니라 규칙이 된다. 플랫폼 tail 봉투가 따로 싣는 요청 헤더(IP 포함)는 우리 소관이 아니고, 요청 본문은 봉투에 없다(실측) |
| `rules.js` 에 `fetch` 0건 | 판정 경로에 네트워크가 들어오면 결정론이 깨진다 |

### 2-5. ⑤ LLM 검증층 — `node scripts/test_verify.mjs`

**Why.** 언어 모델은 판정하지 않는다. 그런데 **문장을 쓰는 순간 숫자를 쓸 수 있다.** 이 계층은 "쓰지 않기로 했다"를 코드로 강제하는 자리다. 그리고 이 함수들은 **우리 OpenAI 키를 쓰는 엔드포인트**이기도 하다.

**What / How.** 모델을 호출하지 않는다. 검증층 함수만 고정 문자열로 돌린다.

| 검사 | 지키는 것 |
|---|---|
| 오리진 경계 | 남의 사이트가 우리 키를 쓰지 못한다. `evil.example`, 오리진 없는 요청, `…pages.dev.evil.com` 접두어 흉내, http 를 막는다. **로컬 개발 예외는 요청 호스트가 localhost 일 때만** — 배포본에서 `http://localhost` 가 통과하던 것을 막았다(2026-09-18 실측) |
| 속도 제한 | 오리진을 먼저 보고, 통과해야 IP 단위로 센다 |
| 숫자 금지 | 십진 숫자(전각 포함)와 한글 금액 표현을 걸러낸다. 조문 표기(`제6조의3`)의 숫자는 예외다. **"이 글"·"만나서"의 이·만은 걸리지 않아야 한다** — 다 걸면 정상 인사말이 한 줄도 남지 않는다 |
| 법 결론 금칙어 | `위법`·`청구할 수 있습니다` 등. 표기 규칙 위반어(`미사용`)도 같은 목록이다 |
| 범위 검사 | "구억육천만원"을 9,600으로 읽고 confidence 0.98을 냈던 실측 사례. 자릿수 사고는 **confidence 로 못 잡는다** |

## 3. 데이터 품질 게이트 — 배포를 멈추는 검사

**Why.** 스냅샷은 다시 만들 때마다 화면에 바로 반영된다. 원천이 망가진 날 **자동으로 화면에 반영되는 것**이 이 서비스의 가장 큰 단일 위험이다. 검사는 코드를 지키고, 게이트는 데이터를 지킨다.

**What / How.** `scripts/build_assets.py` 의 `validate()` 가 집계 직후에 돌고, 하나라도 걸리면 **자산을 쓰지 않고 exit 1** 한다. 옛 스냅샷이 그대로 남으므로 배포본은 계속 동작한다.

| # | 기준 | 임계값 | 2026-09-18 실측 | 걸리면 |
|---|---|---|---|---|
| G1 | 코호트 표본 | 모든 코호트 `n ≥ 3` | 11,715개 전부 통과 | 중단 |
| G2 | 인상률 벡터 정렬 | 오름차순 | 통과 | 중단 |
| G3 | 5% 초과 건수 ≤ 표본 수 | 집단별 | 통과 | 중단 |
| G4 | 코호트 중앙값 범위 | −90~300% | 통과 | 중단 |
| G5 | 전세→전세 갱신 표본 | ≥ 1,000건 | 85,691건 | 중단 |
| G6 | 갱신 행의 종전 보증금 결측률 | ≤ 0.5% | **0.21%** (갱신 176,066행) | 중단 |
| G7 | 유형별 갱신요구권 양성 토큰 비율 | ≥ 15% | 아파트 44.13% / 오피스텔 30.84% / 연립다세대 31.28% / 단독다가구 **22.41%** | 중단 |
| G8 | 같은 비율의 **직전 스냅샷 대비 낙폭** | −5%p 이내 | 직전 스냅샷과 비교(첫 빌드는 건너뜀) | 중단 |

**G7의 임계값을 25%가 아니라 15%로 둔 이유**: 명세 초안은 25%였는데 실측 최저가 단독다가구 22.41%다. 실제 데이터로 돌면 첫날부터 막힌다. 임계값은 **관측된 바닥 아래**에 두어야 붕괴만 잡고 정상을 막지 않는다. G8이 상대 낙폭을 따로 보므로 절대 하한을 낮춰도 감시가 비지 않는다.

**G6·G7이 지키는 것**은 숫자가 아니라 **표기의 성립 조건**이다. 갱신 행의 갱신요구권 칸이 비기 시작하면 "행사 기록 없음"이라는 라벨 자체가 의미를 잃는다. 그때는 숫자를 고치는 것이 아니라 **말을 바꿔야 한다.**

## 5. 회귀 감시 — 원천이 조용히 바뀌는 경우

**Why.** 공표 데이터는 예고 없이 바뀐다. 열이 사라지거나 값이 비어도 파이프라인은 에러 없이 통과하고 **화면의 숫자만 조용히 틀려진다.** 이것이 이 서비스에서 가장 탐지하기 어려운 고장이다.

| 고장 | 지금 잡는 방법 | 반응 |
|---|---|---|
| 채움률 급락 | G6·G7(절대), G8(직전 스냅샷 대비 −5%p) | 빌드 중단 |
| 표본 급감 | G5 (전세→전세 갱신 1,000건 미만) | 빌드 중단 |
| 호출 실패가 조용히 빠짐 | `anchors.build.failed_jobs` / `zero_jobs` 를 자산에 남긴다. 아파트 0건 조합은 이름을 찍는다 | 사람이 본다. 실패분만 `--retry` 로 다시 받는다 |
| 이상치 유입 | `anchors.build.dropped_outliers` (2026-09-18: 61건) | 사람이 본다 |
| 수치 의미 변경 | **아직 자동으로 잡지 못한다** — §8 | — |

> 실패 조합을 기록하는 이유: 공공 API 를 8워커로 두드리면 429가 난다. 조용히 빠지면 오피스텔 80개 조합이 통째로 없는 채 자산이 만들어진다. 실제로 그렇게 만들어진 적이 있다.

## 6. 분기 — 화면이 끝나는 방식

**Why.** 모든 상태에 **사용자가 읽는 결말 문장**이 있어야 한다. 결말 문장이 없는 분기는 "조용한 통과"가 되고, 조용한 통과는 이 서비스가 없애려는 바로 그 실패다.

**What / How.** 02-SPEC §5의 모드 M-01~M-11 과 오버레이 O-01~O-06 이 목록이다. 자동 검사는 산술까지만 덮고, **결말 문장 자체는 §7의 사람 확인**으로 본다. 브라우저 자동화를 넣지 않았다 — 그 사실을 숨기지 않는다.

| 분기 | 입력 | 화면이 끝나는 방식 | 덮는 검사 |
|---|---|---|---|
| M-01 서울 밖 | 자치구 = 서울 밖 | 분포 미표시 + 기한·문안은 동작 | 사람 |
| M-02 마감 경과 | 오늘 > 마감 | 합의·묵시적 두 경로 | rules(R6) + 사람 |
| M-03 스냅샷 실패 | 앵커·샤드 읽기 실패 | **분포 판정 중단**, 입력만으로 되는 산술은 계속 | 사람 |
| M-04 월세 혼합 | 월세 > 0 | 보증금 비교 잠금 + 환산 경로 | rules(R7) + 사람 |
| M-08 결과 0건 | 다섯 단계 전부 0건 | 단계별 건수 + 판정 불가 | rules(사다리) · **배포본에서는 도달 불가** |
| M-09 표본 부족 | 확장 후에도 n < 3 | 백분위 미표시 + 단계별 건수 | rules · **배포본에서는 도달 불가** |
| M-11 자릿수 확인 | 보증금이 코호트 중앙값의 1/3~3배 밖 | 되묻고, 확인 전까지 그 금액에서 나온 화면을 전부 보류 | rules(R2-1) + 사람 |
| O-01 갱신권 기사용 | 사용자 입력 "예" | 1회 한정 안내 + **입력 의존 고지** | 사람 |
| O-02 실거주 통보 | 사용자 입력 "실거주" | 진위 판정 없음 + 기록 양식 | 사람 |
| O-06 순증 | 감액분 0 & 월세 > 0 | 전환율 대신 연 부담률, **분포와 비교 안 함** | rules(R7) |

## 7. 사람이 눈으로 — 배포 전 체크리스트

자동화로 잡히지 않는 것만 남긴다. 10분 안에 끝난다.

- [ ] 로그인 없이 URL 을 열어 **만기일 하나만 입력**해도 법정 기한 타임라인이 나온다.
- [ ] 상단 **데이터 기준일**이 오늘 기준으로 말이 되는 날짜다.
- [ ] 데이터 한계 배너 4줄(기준일 / 서울 / 단지 식별 / 신고된 결과이지 예측이 아님)이 보인다.
- [ ] 행사 기록 없는 집단의 라벨이 **"행사 기록이 없는 갱신 계약"**이다. "미사용"이 화면에 없다.
- [ ] 표본 수 `n` 이 판정 문장 안에 그대로 찍혀 있다.
- [ ] 코호트를 넓혔으면 **어느 단계 기준인지**가 문장에 있다.
- [ ] 표본 부족 케이스를 일부러 넣었을 때 숫자가 아니라 **"판정하지 않습니다"**가 나온다.
- [ ] 월세를 넣으면 보증금 백분위 화면이 **잠기고 그 이유가 보인다**.
- [ ] 아파트가 아닌 유형을 고르면 **건물명 칸이 사라진다**.
- [ ] 제시 조건을 비운 채 '인상률로' 탭에서 판정하면 **그 탭 안에서 오류 메시지가 보이고** 포커스가 그리로 간다.
- [ ] 검증이 실패하면 **이전 판정 화면이 사라진다**.
- [ ] 모바일 폭에서 표가 가로로 넘치지 않고 숫자가 잘리지 않는다.
- [ ] 개인정보 입력 칸이 없다 — 이름·연락처·동·호수·계약서 업로드 전부 없다.
- [ ] 법률 경계 문구와 창구(분쟁조정위 / ☎132 / 전월세보증금지원센터) 링크가 살아 있다.
- [ ] **`dist/og.png` 의 숫자가 앵커와 같다.** 이미지 안의 글자는 검사가 읽지 못한다(§8).
- [ ] 배포 후 다른 오리진에서 `/api/parse` 를 직접 불러 **막히는지** 확인한다.
- [ ] 붙여넣기로 읽은 금액이 **확인 버튼을 누르기 전에는** 판정 입력 칸에 들어가지 않는다.
- [ ] 한글이 시스템 글꼴로 뜨고 라틴 숫자·영문이 Atkinson 으로 뜬다(글꼴 자가 호스팅).
- [ ] §6-1 의 전 경로를 다시 밟는다. **넓게 고친 날에는 반드시 한다** — 회귀를 잡을 브라우저 자동 검사가 없다.

## 8. 아직 없는 것 (정직하게 남긴다)

1. **브라우저 자동화가 없다.** 결말 문장·포커스 이동·숨은 탭은 사람이 본다. §6의 "사람" 칸이 그 목록이다.
2. **OG 이미지의 숫자를 검사가 읽지 못한다.** `dist/og.png` 는 2026-09-18 앵커 값으로 손수 만든 정적 파일이고 생성 스크립트가 없다. 메타 태그의 숫자는 §2-3이 검사하지만 이미지 안의 글자는 사람이 본다.
3. **수치의 의미 변경을 잡지 못한다.** 행사 기록 없는 집단의 5% 초과 비율이 크게 움직였을 때, 시장이 움직인 것인지 원천의 의미가 바뀐 것인지 코드는 구분하지 못한다. 지금은 사람이 `anchors.json` 을 직접 비교한다.
4. **최근 계약의 신고 지연을 수치로 못 낸다.** 수집 캐시가 계약일을 남기지 않아 월별 채움률을 재현할 수 없다. 배너는 `계약구분` 공란 비율(2.20%)만 근거로 쓰고, "최근 계약일수록 빠질 수 있다"는 **기제에 대한 설명이지 측정이 아니다.**
5. **빈칸=미행사 가정이 틀렸을 경우.** 등급 B 판단이고 데이터로는 확정할 수 없다. 검사는 이 가정의 **일관된 적용**만 보증한다.
6. **2020-12-10 이전 체결분의 기한 기준**은 두 날짜를 모두 보여 주는 것으로 처리했고, 어느 쪽이 맞는지는 판정하지 않는다.
