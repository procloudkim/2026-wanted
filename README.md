# 갱신 기준선

전월세 계약 갱신을 앞둔 세입자가, 집주인이 제시한 조건이 **같은 조건의 실제 갱신 계약들 사이에서 어디쯤인지** 공개 실거래 데이터로 확인하고 다음 행동을 정하도록 돕는 웹 서비스.

판정은 코드가 한다. 언어 모델은 **판정 앞뒤에만** 있다 — 사용자가 붙여넣은 문장을 계산 입력으로 바꾸고, 회신 문안의 인사말과 맺음말을 쓴다. **숫자가 든 문장은 전부 코드가 쓴다.**

## 이 서비스가 답하는 것

- 제시받은 인상률은 같은 조건 갱신 계약 중 어디에 있는가
- 갱신요구권을 행사한 계약과 그렇지 않은 계약의 인상률 분포는 어떻게 다른가
- 지금 나가면 새로 구할 때 얼마를 더 내야 하는가
- 법이 정한 갱신 요구 기간에서 오늘은 어디인가

## 측정된 사실 (2026-09-18)

국토교통부 전월세 실거래가 4종 API를 서울 25개 자치구 × 최근 12개월(2025-10~2026-09) 호출해 직접 계산했다. 원본 596,178행, 그중 **전세→전세 갱신 85,691건**이 비교 대상이다. 월세가 섞인 계약은 보증금 단독 비교가 성립하지 않아 제외했다.

| 구분 | 표본 | 5% 초과 비율 | 상위 10% 인상률 |
|---|---|---|---|
| 갱신요구권 행사 기록 있음 | 40,814건 | **0.37%** | 5.00% |
| 행사 기록 없음 | 44,877건 | **31.95%** | 15.87% |

- 전세→전세 갱신의 **26.51%**가 정확히 +5.00%다.
- 행사 기록 없는 초과 건의 상한 대비 차액은 **건당 중앙값 2,400만원**이다. 이 값은 위법 금액이 아니라 갱신요구권을 행사했을 때의 상한과 실제 계약의 차이다.

주택 유형별로 갈린다. 행사 기록 있는 쪽은 네 유형 모두 5% 초과가 **1% 미만**이다.

| 유형 | 표본 | 행사 기록 없는 쪽의 5% 초과 | 그 집단 상위 10% |
|---|---|---|---|
| 아파트 | 56,517건 | 39.57% | 17.86% |
| 단독·다가구 | 5,070건 | 46.69% | 25.00% |
| 연립·다세대 | 17,279건 | 17.66% | 8.70% |
| 오피스텔 | 6,825건 | 8.04% | 5.00% |

> **모수를 섞지 않는다.** 위 숫자는 전부 한 계열이다 — 국토부 4종 API, 서울 25개 자치구, 최근 12개월. 화면·문서·OG 메타에 뜨는 값은 항상 `dist/data/anchors.json` 의 것이고 그 옆에 모수가 함께 적히며, 어긋나면 `node scripts/test_anchors_docs.mjs` 가 깨진다. 제품을 정하기 전에 서울시 파일로 같은 질문을 먼저 물었고, 그 계열은 모수가 달라 `docs/01-PRD.md` 부록 A에만 둔다.

## 실행

```bash
cp .env.sample .env      # 키를 채운다. .env 는 커밋하지 않는다
set -a; . ./.env; set +a

./scripts/test_all.sh                       # 키도 네트워크도 없이 도는 검증 전부
python3 scripts/build_assets.py             # 수집 → 집계 → 검증 → dist/data 출력 (약 3분, 1,200회 호출)
python3 scripts/build_assets.py --retry     # 429 등으로 빠진 조합만 다시 받는다
python3 scripts/build_assets.py --from-cache # 네트워크 없이 재집계 (스키마를 고칠 때)

npx wrangler pages dev dist                 # 로컬 실행 (함수 포함)
npx wrangler pages deploy dist              # 배포
```

수집분은 `data/raw-rows.json.gz` 에 남는다(커밋하지 않는다). 집계 스키마를 고칠 때 1,200회를 다시 부르지 않기 위한 캐시다.

배포 환경변수는 호스팅 대시보드에서 넣는다 — `OPENAI_API_KEY`(필수), `OPENAI_MODEL`(선택, 기본 `gpt-5.4-mini`). 원천 API 키는 **배포 환경에 넣지 않는다.** 런타임이 원천을 호출하지 않으므로 필요 없다.

**막지 못하는 것.** 오리진 헤더는 브라우저만 못 속인다. `curl` 로 오리진을 위조하면 통과한다. 엣지 레이트리밋(WAF 규칙)은 자체 도메인(zone)이 있어야 쓸 수 있고 `*.pages.dev` 에는 걸 수 없다. **이 경로의 최종 방어선은 제공자 쪽 지출 한도다** — OpenAI 대시보드에서 이 키에 월 한도를 걸어 두는 것이 실질적인 상한이다.

## 구현하면서 바꾼 결정

되돌릴 수 있는 결정이라 분기 문서를 만들지 않고 여기에 이유만 적는다. **결정 자체는 `docs/02-SPEC.md` 본문에 반영돼 있다** — 명세와 구현이 갈린 채로 두지 않는다.

1. **코호트 자산은 분위수 대신 정렬된 인상률 벡터를 싣는다.** 분위수만 담으면 "상위 몇 %"를 정확히 낼 수 없다. 5% 초과·동률 건수만은 벡터가 아니라 **원본 행의 정수 비교 결과**를 따로 싣는다 — 인상률을 0.01%p 정수로 접으면 5.0026% 같은 계약이 정확히 5.00%로 내려앉아, 행사 기록 있는 쪽의 5% 초과가 0.37%에서 0.01%로 바뀐다.
2. **폴백 사다리에 "단지 전체 면적" 단계를 넣어 5단계로 한다.** 단지·면적대 → 단지 전체 → 법정동·면적대 → 법정동 → 자치구.
3. **문안 생성에서 언어 모델은 숫자가 든 문장을 만들지 않는다.** 인사말과 맺음말만 쓰고, 숫자 문장은 전부 브라우저의 코드가 쓴다. 모델에게 재서술을 맡겼더니 숫자가 맞는데 라벨이 바뀌었다 — 코호트 전체 316건을 "행사 기록이 있는 316건"으로, 5% 상한액을 "제시된 보증금"으로 썼다. 숫자 화이트리스트로는 잡히지 않는 오류라 검증 대신 경로를 끊었다. 그래서 검증도 단순해졌다: 모델이 쓴 문장에 숫자나 금액 표현이 있으면 버린다. 한글 수사를 전부 잡지는 않는다 — "이 글"·"만나서"의 이·만까지 걸면 정상 인사말이 한 줄도 남지 않아서, 단위에 붙은 금액 표현만 본다.
4. **서울 밖(M-01)에서도 5% 상한 금액과 인상률은 보여 준다.** 분포 숫자가 아니라 입력값만으로 되는 산술이고, 5% 상한은 지역과 무관한 법정 기준이다.
5. **자릿수 사고를 코호트로 되묻는다(M-11).** 금액이 10배 틀려도 종전과 제시가 같은 배율이면 인상률이 정상이라 어떤 비율 검사도 통과한다. 바깥 기준이 필요해서 같은 코호트의 신규 전세 보증금 중앙값과 대조하고, 1/3~3배 밖이면 **판정을 멈추고 되묻는다.** 버리는 것이 아니라 되묻는 것이다 — 사용자가 맞다고 하면 그대로 판정한다.
6. **`/assets/*` 는 `no-cache` 다.** 파일명에 콘텐츠 해시가 없어서 긴 캐시를 걸면 배포한 수정이 반영되지 않는다(실측: `max-age=3600` 으로 한 시간).
7. **서울시 OA-21276(262만 행) 수집은 이번 빌드에서 뺐다.** 일일 호출 한도가 미확인이고, 코호트 분포는 국토부 4종만으로 나온다. 원천이 하나이므로 별칭 사전·출처 병합·중복 묶음 판정도 만들지 않았다.
8. **단지 단위 비교는 아파트에만 한다.** 원천이 단지 일련번호를 주는 유형이 아파트뿐이다 — 오피스텔·연립다세대·단독다가구는 596,178행 전부 비어 있다. 명세 초안은 오피스텔도 단지 단위로 잡았는데, 그러면 건물명 칸이 뜨고 자동완성 목록은 비어 있고 이름을 치면 판정이 막힌다. **원천에 없는 것을 있다고 가정하면 그 대가는 사용자가 치른다.**
9. **환산 전환율 분포를 상수로 두지 않는다.** 판정 산술과 같은 빌드에서 나온 `anchors.convert` 를 읽는다. 상수로 두면 다른 두 분포와 기준일·모수가 조용히 갈린다.

## 한계

- 데이터는 신고된 계약의 결과이며 예측이 아니다.
- 서울과 수도권 표본이 가장 두껍다. 그 밖의 지역은 유형에 따라 표본이 얇다.
- 단독·다가구는 원천에 건물명과 지번이 없어 같은 건물끼리 비교할 수 없다.
- 이 서비스는 통계를 보여 주어 의사결정을 돕는다. 법률 자문이 아니다. 개별 계약의 법적 판단은 전문가에게 확인해야 한다.
